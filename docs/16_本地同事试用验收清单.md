# 智聘 · 内部小范围试用验收清单

这份清单用于公司内部真实数据小范围试用。原则很简单：先确认部署和备份，再用一条 1 HC 需求跑通完整闭环，最后才扩大人数。

## 1. 上线前检查

- [ ] 当前版本是负责人指定的独立试用分支和提交号。
- [ ] GitLab 流水线全部结束，没有任务一直处于运行或等待状态。
- [ ] `.gitlab-ci.yml` 没有旧版 GitLab 不支持的 `workflow.auto_cancel`。
- [ ] 数据库、附件和备份使用长期目录，不使用 `/tmp`。
- [ ] `internal-trial` 就绪检查全部通过。
- [ ] 已完成真实备份，并记录备份目录：`____________________________`。
- [ ] 招聘专员、招聘主管和面试官都能用自己的账号密码登录。
- [ ] 简历 AI 和岗位画像 AI 均关闭；AI 不可用不会阻塞核心流程。

## 2. 招聘需求

- [ ] 招聘专员创建一条 1 HC 需求，记录需求编号：`________________`。
- [ ] 职位名称、负责人、部门、城市、目标日期和 JD 保存正确。
- [ ] 重复点击提交不会创建两条相同需求。
- [ ] 招聘主管可以看到该需求和对应的负责人。

## 3. 简历入库与候选人流程

- [ ] 从该需求上传简历，系统保留原始文件并提示人工确认。
- [ ] 人工补全基本资料并保存后，候选人自动进入该需求“待筛选”。
- [ ] 招聘需求编号和候选人 ID 对应正确，没有串到其他需求。
- [ ] 再次确认或重复推进不会生成重复阶段记录。
- [ ] 招聘专员可以按“待筛选 → 面试 → Offer”逐步推进。

## 4. 面试

- [ ] 招聘专员安排面试官、轮次和时间，重复提交不会创建两场相同面试。
- [ ] 未来时间的面试不能提前标记为已完成。
- [ ] 面试完成后，指定面试官可以提交评价。
- [ ] 面试评价保存后候选人阶段不自动改变，由招聘专员明确确认推进。
- [ ] 面试管理、候选人详情和招聘进度中的信息一致。

## 5. Offer 与入职

- [ ] 招聘专员保存 Offer 草稿并提交审批。
- [ ] 招聘主管完成审批，招聘专员完成发送登记。
- [ ] 候选人接受后可以登记入职；各步骤顺序不能跳过。
- [ ] 重复点击同一步骤不会产生重复 Offer 或重复历史记录。
- [ ] 入职后候选人阶段显示“已入职”，1 HC 需求的入职人数显示 1。

## 6. 看板与权限

- [ ] 招聘进度、招聘需求详情和数据看板显示同一个最终阶段与人数。
- [ ] 招聘专员能打开招聘需求、简历库、招聘进度、面试、Offer、数据看板。
- [ ] 面试官只能处理分配给自己的工作，不能操作 Offer 或系统设置。
- [ ] 招聘主管可以确认需求和 Offer，但不会代替招聘专员执行日常推进。
- [ ] 未登录不能直达业务页面，普通账号不能通过手输地址进入越权页面。

## 7. 稳定性与问题记录

- [ ] 每个核心页面连续打开两次，不白屏、不无限转圈。
- [ ] 页面失败时有明确提示和重试入口。
- [ ] 连续操作后刷新页面，需求、候选人、面试、Offer 和看板仍保持一致。
- [ ] 每个问题都记录账号、需求编号、候选人 ID、操作步骤、实际结果、期望结果和截图。
