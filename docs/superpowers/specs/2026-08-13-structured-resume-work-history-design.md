# 结构化简历工作经历合并展示设计

## 背景

简历库的候选人详情当前使用通用字段宫格展示工作经历。公司、时间、岗位和经历说明被拆成彼此独立的信息块，用户难以快速判断它们是否属于同一段任职经历。

## 目标

每段工作经历作为一个完整卡片展示，让公司、岗位、任职时间和职责成果之间的归属关系清楚，同时保持原始结构化数据不变。

## 已确认方案

采用方案 A：

- 公司名作为卡片头部的主信息。
- 岗位紧随公司名显示在左侧次级位置。
- 任职时间位于同一头部右侧，以轻量标签展示。
- 经历说明、主要职责、主要成果等长文本放在头部下方，并用分隔线与头部区分。
- 窄屏时头部自动换行，时间移动到公司和岗位下方，不挤压公司名。

## 数据兼容

- 仅对“工作经历”段落中的对象列表启用专用布局。
- 支持公司字段 `company`、岗位字段 `position` / `title` / `role`、时间字段 `duration` / `period`，以及 `start_date` + `end_date` 的组合。
- 支持经历说明 `description` / `desc`、职责 `responsibilities` / `responsibility` 和成果 `achievements`。
- 未识别的补充字段仍使用现有通用展示，避免丢失真实简历信息。
- 空字段不显示空标签；数组、对象或多行文本继续安全展示。

## 组件边界

- 在 `StructuredResumeView` 内新增工作经历专用展示组件。
- 通用 `ResumeValue` 和其他简历段落保持原行为，避免影响教育、项目、技能等内容。
- 字段识别与时间合并放在可单测的纯函数中，视图只负责展示。

## 验收标准

1. 张征的每段工作经历只显示为一个整体卡片。
2. 同一段经历的公司、岗位和时间处于同一头部区域。
3. 经历说明位于对应头部下方，不再混在字段宫格中。
4. 缺少岗位、时间或说明时布局不出现空白标签，也不报错。
5. 未识别字段仍可见，其他结构化简历段落不受影响。
6. 前端契约测试、类型检查、Lint 和生产构建通过。

## 非目标

- 不修改简历解析结果或后端接口。
- 不纠正解析器把项目经历误归为工作经历的问题。
- 不改原版简历预览、编辑和下载流程。
