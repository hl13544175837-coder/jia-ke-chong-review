# 招聘系统安全加固设计

日期：2026-08-06  
目标分支：`test`

## 1. 目标

本轮只修复已经确认需要处理的安全问题，并保持现有产品流程不变：

1. 人力总监继续拥有全组织候选人查看权限，但权限必须显式授权；未知角色默认无权查看。
2. 修复可伪造 IP 绕过登录限流和限流记录无限增长的问题。
3. 下载地址不再携带 JWT 登录令牌。
4. 防止 AI 助手把候选人、简历、面试等敏感内容发送到外部搜索服务。
5. 用小改动修复并发重复提交问题。
6. 限制 AI 面试答案的格式、数量、长度和调用频率。
7. 防止 CSV 字段被 Excel 等软件当成公式执行。
8. 不再向普通用户返回服务器内部异常详情。
9. 本轮不修改“密码最短 6 位”的规则。

## 2. 不在本轮范围内

- 不引入 Redis、消息队列或新的外部基础设施。
- 不修改人力总监的业务定位和页面导航。
- 不把现有登录体系整体改造成 Cookie 会话。
- 不调整密码长度、复杂度或多因素认证。
- 不处理与上述问题无关的重构和界面优化。

## 3. 方案设计

### 3.1 候选人权限改为显式授权

候选人可见范围按照角色明确判断：

- `admin`、`manager`、`hr_director`：可查看当前组织全部有效候选人。
- `recruiter`：只看本人负责及暂未分配负责人的候选人。
- `interviewer`：只看分配给本人的候选人。
- 其他或异常角色：返回空查询，不得默认放行。

这样既保留人力总监的高权限，又避免未来新增或拼错角色时意外获得全部候选人权限。

### 3.2 登录限流信任边界

- 默认使用连接到 Flask 的真实来源地址，不直接相信用户提交的 `X-Forwarded-For`。
- 新增明确的受信代理跳数配置。只有部署方配置了代理跳数时，才从转发链中解析客户端地址。
- 限流桶改为有上限、可清理的内存结构；过期桶会被移除，达到上限时优先清理最旧记录。
- 限流状态加线程锁，避免多线程服务同时修改同一桶。
- 登录接口继续使用现有频率规则，不改变正常用户体验。

### 3.3 下载令牌不进入 URL

- BOSS 简历和扩展下载接口改用标准 `Authorization: Bearer ...` 请求头。
- 前端使用已登录请求下载 Blob，再生成浏览器临时地址触发保存。
- 后端不再接受 `?token=`，旧链接返回未认证，防止继续产生带令牌的网址和日志。
- 下载权限仍限制为 recruiter、manager、admin。

### 3.4 AI 外部搜索出网控制

- AI 自动调用外部搜索默认关闭，由后端配置明确开启。
- 即使开启，也在调用外部程序前检查搜索词，拒绝手机号、邮箱、身份证样式、令牌样式和明显候选人隐私内容。
- 被拒绝时只返回固定提示，不把敏感搜索词写入错误响应。
- 系统内数据库查询和普通 AI 对话不受影响。

### 3.5 简化的幂等并发保护

- 收到带 `Idempotency-Key` 的写请求时，业务逻辑执行前先创建一条“处理中”记录。
- 相同请求同时到达时，只允许第一个继续，其他请求返回“请求处理中”。
- 成功后把处理中记录更新为最终响应，后续重试直接复用结果。
- 业务失败或返回非成功状态时删除占位记录，允许用户修正后重试。
- 不新增数据库表和迁移，复用现有幂等记录表的状态字段表达处理中状态。

### 3.6 AI 面试输入限制

- `qa_pairs` 必须是数组，每项必须是包含字符串 `q`、`a` 的对象。
- 限制问答条数、问题长度、答案长度和全部文本总长度。
- 格式错误返回 400，不再触发服务器 500。
- 接口增加单 IP 调用频率限制，复用现有限流中间件。
- 权限和需求/候选人范围检查保持不变。

### 3.7 安全 CSV 输出

- 新增统一 CSV 单元格安全函数。
- 文本去除前导控制字符后，如果首字符为 `=`、`+`、`-`、`@`，则增加安全前缀，阻止表格软件当成公式。
- 候选人 CSV 和管理分析 CSV 共用该函数。
- 数字、日期和普通文本保持原样。

### 3.8 对外错误信息收口

- AI、搜索和简历解析的详细异常继续记录在服务器日志中。
- API、SSE 和候选人页面只返回稳定的中文提示和错误代码。
- 不返回文件路径、内部地址、第三方响应正文、模型配置或异常堆栈。
- 保留现有日志告警能力，方便开发和运维排查。

## 4. 测试策略

遵循测试驱动开发：每项先增加会失败的回归测试，再写最小修复。

1. 权限测试：人力总监可查看同组织全部候选人；异常角色看不到候选人；跨组织始终隔离。
2. 限流测试：未配置受信代理时伪造头无效；配置一跳代理时解析正确；过期桶和超量桶会清理。
3. 下载测试：查询参数令牌被拒绝；请求头令牌成功；不同角色权限不变。
4. AI 出网测试：默认关闭；开启后普通市场查询可用；手机号、邮箱和候选人隐私查询被拒绝。
5. 幂等测试：处理中请求返回冲突；成功结果可重放；失败后可重试。
6. AI 面试测试：错误类型、缺字段、超数量、超长度返回 400；正常输入继续生成报告；频率超限返回 429。
7. CSV 测试：四种公式开头均被安全处理；普通文本和数字不变；两个导出入口都覆盖。
8. 错误信息测试：模拟包含内部路径或密钥字样的异常，响应中不得出现原始异常内容。

## 5. 验证标准

完成前必须获得以下新鲜证据：

- 新增安全回归测试全部通过。
- 相关后端测试全部通过。
- 后端完整测试套件无新增失败。
- 前端测试、类型检查和生产构建通过。
- `npm audit --omit=dev` 与 Python 依赖审计结果被记录；不在本轮修复的依赖预警要明确说明。
- `git diff` 只包含本轮安全加固及相应测试，不覆盖用户其他改动。

1. 每个问题原来是什么。

3. 用户使用上是否有变化。
4. 哪些测试证明修复有效。
5. 哪些风险因本轮范围决定仍然保留。
