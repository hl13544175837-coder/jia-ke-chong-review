# 招聘全流程真实闭环优化设计

> 确认日期：2026-07-27
>
> 适用入口：`readdy-frontend`，本地端口 `5190`
>
> 状态：用户已确认实施；OA、企业微信、短信、邮件和候选人线下沟通属于外部边界，不用假数据冒充送达。

## 1. 目标与完成定义

在不改变 React/Vite + Flask/SQLAlchemy 技术栈、不新增第二套权限或平行业务后端的前提下，把当前 5190 收敛为一套可刷新、可跨真实账号、可追溯的招聘闭环。

完成必须同时满足：

1. 招聘专员能完成需求、简历、业务筛选、面试、决策、Offer 和入职。
2. 业务负责人 / 面试官只看到分给自己的筛选和面试任务，并能提交受状态约束的结论。
3. 招聘经理能查看团队事实、处理跨专员流程，并且与招聘专员看到同一套业务数据。
4. 每个写操作刷新后仍存在，阶段、任务、反馈、Offer 与 HC 数据在数据库中真实变化。
5. 旧演示入口不能再产生与真实主线不一致的业务操作。
6. 原 12 个问题逐项回归通过，图片中的 9 个系统内阶段全部走通。

## 2. 图片九阶段到系统能力的映射

| 图片阶段 | 系统内完成动作 | 外部边界 |
|---|---|---|
| 1 需求生效 | 创建/审批 Demand，绑定 HC、招聘负责人、业务负责人和 JD 快照 | OA 自动承接暂不接；本地从需求页面创建 |
| 2 导入并解析简历 | 上传 PDF/DOCX/图片/ZIP，生成候选人档案并关联当前 Demand | 候选人投递/内推通知不伪造 |
| 3 推送业务初筛 | 在需求内筛选、预览简历、勾选并推送指定业务负责人 | 企业微信任务卡暂不发送；站内通知与待办真实落库 |
| 4 业务初筛 | 面试官查看中文结构化简历、原件、JD 和 HR 备注，提交通过/不合适/需补充 | 企业微信按钮回调暂不接；站内任务完成并回传 |
| 5 线下协调 | 系统明确显示“待协调”，由招聘专员记录时间、地点、方式 | 电话/微信/现场沟通不伪造成功 |
| 6 创建面试 | 创建/修改/取消真实 assignment，检查时间、内部冲突并通知面试官 | 企业微信日程同步暂不接；站内日程与提醒真实落库 |
| 7 面试评价 | 到时后面试官提交满意/待定/不满意与备注，可受控修改 | 企业微信评价回调暂不接；系统内反馈真实落库 |
| 8 招聘专员决策 | 同页选择下一轮、增加面试官、淘汰或转入 Offer；所有动作受阶段规则约束 | 无外部依赖 |
| 9 Offer 与入职 | 草稿、审批、发放、接受/拒绝、确认入职；接受时锁定 HC，拒绝/撤回释放名额 | 外部 Offer 送达和电子签暂不接；站内状态机完整 |

## 3. 产品与架构设计

### 3.1 单一真实入口

- `/interviews` 是招聘侧唯一面试工作台；`/dashboard/interviews` 重定向到它。
- `/offers` 是唯一 Offer 工作台；`/dashboard/offers` 重定向到它。
- Dashboard 卡片、待办、通知和深链全部指向真实页面，不保留可写的旧演示工作台。
- `/kanban` 的阶段能力保留为流程服务入口，但面试结果的高频下一步直接在真实面试页完成。
- 本地假角色切换关闭；验收使用 `hr01`、`manager01`、`interviewer01` 等真实账号，避免界面角色和后端 Token 不一致。

### 3.2 需求内候选人工作区

- 在当前需求右侧工作区提供关键词、城市、学历、技能、来源、流程状态、阶段、最低技能分、可操作状态和排序筛选。
- 候选人列表分页读取真实后端数据，不再静默截断前 50 人。
- 每张候选人卡片分离“查看简历”和“勾选”动作；查看时展示原始简历、中文结构化画像、当前/最近需求、匹配分、命中和缺失技能。
- 支持“只看可加入/可转入”“只看当前需求可推送”，不可操作候选人给出原因和下一步。
- 上传简历时携带当前 `demand_id`，上传结果在同一工作区出现。
- Job 未生成结构化技能时，匹配接口返回明确配置状态；页面显示“岗位技能尚未配置”，禁止把未知匹配冒充 0 分。

### 3.3 状态机与防倒退

- `pipeline_service` 是主流程阶段唯一 owner，业务筛选、面试和 Offer 入口必须调用共享规则。
- 发起业务筛选只允许 `pending`、`ai_screen`、`business_review`；进入 `interview`、`offer` 后后端返回稳定 409，前端隐藏或禁用按钮。
- 业务筛选“不合适”和“需要补充”必须填写备注；前后端同时校验。
- 面试反馈不能在未来时间提交；招聘专员“确认已面试”同样不能早于计划时间，且需要二次确认。
- 面试反馈不自动改主阶段。HR 在结果区显式选择：安排下一轮、进入 Offer 或淘汰。
- 下一轮继续处于 `interview` 主阶段，创建递增 `round_sequence` 的 assignment；淘汰必须填写原因；进入 Offer 追加 `offer` 流水后打开 Offer 草稿。
- 已经安排的业务筛选结果显示“查看/调整面试”，不再显示“安排面试”。
- Offer/入职继续使用现有 Offer 状态机；只有 accepted Offer 的 onboard 动作写入 `onboarded` 并减少缺口，拒绝、撤回、过期不减少 HC。

### 3.4 真实工作台与中文信息

- 招聘侧 Dashboard 用真实 Demand、候选人、面试、Offer 和通知生成待办与数量；接口失败显示不可用，不显示伪造的 0。
- 面试官 Dashboard 使用真实业务筛选任务和 assignment，不再混入过期的演示面试。
- 建立共享中文结构化简历视图：基本信息、教育、工作经历、项目经历、技能和摘要；不向业务用户显示 `extracted_info`、JSON 键或重复英文标签。
- 原件缺失时明确说明“当前没有原版文件”，但结构化信息继续可读。

### 3.5 面试排期便利性

- `datetime-local` 最小值为当前时间，服务端拒绝过去时间。
- 选择面试官和时间时，使用系统内已有 assignment 做冲突提示；真正提交仍由后端冲突校验兜底。
- 外部企业微信/日历未接时只显示“站内日程已创建，外部日历待接入”，不展示假忙闲或假送达。
- 取消必须填写原因；已有反馈任务不能取消；修改和取消都写通知与审计。

## 4. 原 12 个问题的关闭方式

| 原问题 | 设计关闭方式 |
|---|---|
| 两套面试页面 | 旧路由重定向、Dashboard 全部改真实入口 |
| 面试反馈后无下一步 | 真实面试页新增下一轮/Offer/淘汰决策 |
| 后期候选人可退回业务筛选 | 共享阶段守卫 + 后端 409 + 前端禁用 |
| 未来面试可提前评价/确认 | 前后端时间校验 + 二次确认 |
| 假角色切换报 Forbidden | 关闭假切换，真实账号验收 |
| 需求内缺少筛选 | 多条件真实查询与快捷筛选 |
| 不能先看完整简历 | 卡片独立预览入口和共享中文简历视图 |
| 只取前 50 人 | 后端分页、总数和前后页 |
| 未配置岗位时全为 0 分 | 返回匹配配置状态并引导补充 JD 技能 |
| 已安排仍显示安排面试 | 联合面试工作台状态显示正确动作 |
| 首页和业务页数据不一致 | Dashboard 全部读取真实 API |
| 简历技术字段难读 | 共享中文结构化展示组件 |

同时补齐三项同类体验：拒绝/需补充原因必填、内部排期冲突提示、关键不可逆动作二次确认。

## 5. 错误、权限与数据一致性

- 401 跳登录；403 显示当前账号无权处理且不给可点击写按钮；409 用大白话说明状态已变化、流程冲突或时间冲突。
- Dashboard 分区独立加载，单个接口失败不拖垮整页。
- 所有写动作使用现有幂等键和服务端锁；批量动作逐人返回结果。
- `demand_id` 始终显式传递；不能用岗位标题或当前页面猜 Demand。
- 面试官不能访问全量候选人、推进流程或管理 Offer；招聘专员只能管理自己负责的 Demand；经理可看本组织团队事实。
- 不新增数据库表或迁移；如实施中发现必须新增持久字段，先停止并补充设计，不直接改 schema。

## 6. 测试与最终验收

### 6.1 自动化

- 后端：阶段守卫、业务筛选备注、未来面试、下一轮 assignment、Offer/HC、RBAC、组织隔离和幂等。
- 前端：路由收口、Dashboard 真实 API、需求内筛选/分页/简历预览、状态化按钮、中文简历、面试决策和外部边界提示。
- 执行后端全量 pytest、Base Agent 测试、两个前端的契约测试、类型检查、lint 和 production build。

### 6.2 三视角真实浏览器闭环

1. 招聘专员创建/选择 Demand，导入或选择候选人并推送业务筛选。
2. 面试官真实账号收到任务，查看简历和 JD，提交通过。
3. 招聘专员收到结果，协调并安排一面。
4. 面试官收到一面任务；未来时间无法评价，到时/确认后提交评价。
5. 招聘专员选择下一轮并安排；面试官完成第二轮评价。
6. 招聘专员转入 Offer，经理审批，招聘专员发放并记录接受。
7. 招聘专员确认入职，Demand 的 onboarded/HC 数量与缺口真实变化。
8. 分别刷新、退出重登并复查三角色页面；检查数据库流水、任务、反馈、Offer 事件和通知。

### 6.3 外部接口边界验收

- OA 未接：系统可手工创建需求并保留未来 `template/business_owner` 契约，不声称 OA 已同步。
- 企业微信未接：系统只显示站内任务/日程/通知真实状态和“外部待接入”，不声称消息已送达。
- 短信、邮件、候选人沟通未接：不显示成功发送，仅保留人工协调记录。
