# 外部 Agent 简历导入 MVP 设计

> 日期：2026-08-07  
> 状态：待用户书面审阅  
> 范围：外部 Agent 向智聘导入在线简历、完整聊天记录和完整简历

## 1. 目标

在不让智聘控制外部 Agent、不改变现有正式招聘流程的前提下，为外部 Agent 提供一个稳定的导入口。

MVP 只解决两件事：

1. Agent 可以把挑选后的 BOSS 在线简历和完整聊天记录导入独立的“在线简历库”。
2. Agent 拿到候选人的完整简历后，可以直接导入现有“完整简历库”。

两个简历库独立存在，不自动关联、不自动搬移、不自动覆盖，也不互相删除。

## 2. 已确认的产品原则

- 在线简历不是必经步骤。Agent 可以只导入少量挑选后的在线简历。
- 完整简历也可以直接导入，不要求系统里先存在在线简历。
- 同一个候选人同时出现在两个简历库中不算冲突。
- 智聘不启动、不调度、不控制外部 Agent，也不在智聘内发送 BOSS 消息。
- Agent 可以自行在 BOSS 上打招呼、聊天和索要完整简历。
- 在线简历库保留完整聊天记录；智聘只负责保存和展示。
- 在线简历可以由所属招聘专员随时手动删除。
- 删除在线简历后，已产生的导入数量仍保留，用于工作量统计。
- KPI 只统计“招聘专员导入了多少份在线简历”，不统计 BOSS 实际收到多少份。
- 一份在线简历只绑定一个招聘专员和该招聘专员的一个 BOSS 账号，不做转交。
- 招聘专员只能查看自己的在线简历。
- 完整简历进入现有正式简历库，继续走当前业务筛选、面试、Offer 和入职流程。
- 原始完整简历与系统中的可编辑结构化信息分开保存。
- 招聘专员可以修改结构化候选人信息；原始简历文件和原始聊天内容按导入内容展示。

## 3. 不在 MVP 中实现

- 不自动判断候选人是否合适或自动淘汰。
- 不新增“待判断、已索要、已获得、不合适”等复杂状态。
- 不做多个 BOSS 账号之间的候选人合并。
- 不自动把在线简历升级成完整简历。
- 不在导入完整简历后删除在线简历。
- 不自动关联在线简历与完整简历。
- 不做在线简历转交。
- 不在智聘里回复 BOSS 消息。
- 不记录每一次结构化字段的人工修改历史。
- 不新增自动重新匹配步骤。
- 不改变现有正式候选人招聘流程。

## 4. 两条独立产品路线

### 4.1 在线简历路线

1. 招聘专员或外部 Agent 已经知道本次对应的具体招聘需求。
2. Agent 在 BOSS 上读取并挑选在线简历，可自行打招呼和继续聊天。
3. Agent 把选中的在线简历、完整聊天记录和来源信息导入智聘。
4. 数据进入该招聘专员自己的“在线简历库”。
5. 招聘专员可以查看结构化信息、完整聊天、对应需求和 BOSS 账号，也可以修改结构化信息或手动删除。
6. 每次成功创建在线简历时，系统记录一条导入事实，用于统计导入数量。

### 4.2 完整简历路线

1. Agent 从 BOSS 聊天或其他允许的来源拿到候选人完整简历。
2. Agent 直接把完整简历原件、结构化信息、来源和具体招聘需求导入现有完整简历库。
3. 系统继续复用现有简历原件保存、简历版本、候选人详情和招聘流程。
4. 是否存在同名在线简历不影响本次导入；MVP 不查找、不关联、不删除在线简历。

## 5. 页面优化

### 5.1 新增“在线简历”菜单

招聘专员侧边栏新增“在线简历”。页面默认只展示当前招聘专员自己的数据。

列表最少展示：

- 候选人姓名或平台展示名
- 对应招聘需求
- BOSS 账号
- 最新一条聊天内容
- 最新聊天时间
- 导入时间
- 编辑
- 删除

详情最少展示：

- 在线简历的全部结构化信息
- 完整聊天记录，按时间顺序展示
- 对应招聘需求
- 招聘专员及其 BOSS 账号
- BOSS 候选人或聊天入口（Agent 提供时展示）
- 编辑结构化信息
- 删除在线简历

页面不增加流程状态、推进按钮和 BOSS 回复输入框。

### 5.2 现有“简历库”保持不变

完整简历仍进入当前简历库。现有候选人详情、原始简历、结构化信息、招聘需求、筛选、面试和 Offer 能力继续复用。

## 6. Agent 导入边界

系统提供一个统一的外部 Agent 导入口。Agent 每次提交时明确数据类型：

- `online`：在线简历、完整聊天和来源信息。
- `full`：完整简历原件、结构化信息和来源信息。

统一导入口支持单份和批量提交。完整简历类型在系统内部复用现有简历上传与入库能力，不再建设第二套正式简历处理流程。

Agent 提交时至少需要提供：

- 数据类型
- 招聘专员身份
- 具体招聘需求
- 来源平台
- BOSS 账号
- 平台候选人或聊天标识
- Agent 本次导入的唯一编号

在线简历还需要提供：

- 结构化在线简历
- 完整聊天记录
- BOSS 候选人或聊天入口（存在时）

完整简历还需要提供：

- 完整简历文件
- 结构化简历信息

Agent 使用系统签发且绑定招聘专员的导入凭证。智聘只校验和接收提交，不反向寻找或控制 Agent。

## 7. 数据保存方式

### 7.1 在线简历

MVP 使用一份独立的在线简历记录保存：

- 组织
- 所属招聘专员
- BOSS 账号
- 具体招聘需求
- 来源平台和来源标识
- 结构化在线简历
- 完整聊天记录
- BOSS 入口
- 导入时间和更新时间

完整聊天记录直接作为一份按时间排序的数据保存，不拆成复杂的聊天系统。Agent 再次同步时提交当前完整聊天快照，系统更新这份记录。

### 7.2 完整简历

继续使用现有候选人、简历原件、结构化简历和简历版本能力。外部 Agent 只是新增来源，不改变正式简历的数据结构和页面读取方式。

### 7.3 KPI 数量

每次成功创建一份在线简历时，记录一条不可因手动删除而消失的“在线简历导入”事实。统计只按招聘专员汇总成功导入数量，不做人员排名、自动评价或奖金判断。

## 8. 权限

- 招聘专员只能查看、编辑和删除属于自己的在线简历。
- 一份在线简历固定绑定一个招聘专员和一个 BOSS 账号，MVP 不支持转交。
- 经理和管理员沿用当前组织内管理权限，用于必要的管理和问题排查。
- 完整简历继续沿用当前简历库权限，不新建第二套权限规则。
- 外部 Agent 的导入凭证只能写入绑定招聘专员范围内的数据。

## 9. 重复提交与失败处理

- 同一个 Agent 导入编号重复提交时，不重复创建数据。
- 在线简历批量导入逐条返回成功或失败，一条失败不影响其他条目。
- 完整聊天更新失败时保留上一次成功内容。
- 完整简历导入失败时不产生半条正式候选人记录。
- 在线简历和完整简历互不回滚、互不删除。
- 页面用招聘人员能看懂的话显示失败原因，不展示内部错误。

## 10. MVP 验收标准

1. 外部 Agent 可以单份或批量导入选中的在线简历。
2. 招聘专员只能在“在线简历”菜单看到自己的数据。
3. 在线简历能展示具体招聘需求、BOSS 账号、结构化信息和完整聊天记录。
4. 招聘专员能修改结构化在线简历并随时手动删除。
5. 删除后在线简历内容不可再查看，但导入数量不减少。
6. Agent 可以不经过在线简历库，直接导入完整简历。
7. 完整简历成功进入现有简历库，并能被现有候选人详情和招聘流程正常读取。
8. 同一个人同时存在于在线简历库和完整简历库时，系统不自动关联、搬移或删除。
9. Agent 重复提交同一个导入编号不会生成重复记录。
10. 智聘没有启动 Agent、发送 BOSS 消息或操纵外部平台的入口。

## 11. 当前产品改动范围

本次只新增或调整：

- 招聘专员侧边栏“在线简历”菜单及列表、详情、编辑、删除。
- 独立的在线简历保存能力。
- 外部 Agent 统一导入口，支持在线简历和完整简历两种类型及批量提交。
- 在线简历导入数量统计。
- 完整简历导入对现有简历上传服务的复用。

现有简历库、候选人流程、业务筛选、面试、Offer、BI 主口径和 BOSS 实验页面不做无关重构。
