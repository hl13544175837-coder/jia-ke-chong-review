# 本地同事试用三批收口设计

## 背景与目标

当前本地版本已经通过多角色主流程、全量测试和构建门禁，可以小范围试用。本轮不增加业务能力，而是把同事试用时最容易造成困惑、误操作或回归的细节收干净。

产品第一性原理是：用户在任何页面都要立即知道“现在发生了什么、下一步能做什么、操作是否安全”。因此本轮只优化状态反馈、测试可恢复性和自动防回归，不改招聘状态机，不新增页面，不接外部接口。

## 方案选择

### 方案 A：每个页面单独修补

改动表面最小，但会继续产生不同文案、不同按钮和遗漏页面。后续每次新增状态都要重复处理，不推荐。

### 方案 B：共享小组件和轻量门禁（采用）

复用现有 React、Node 测试和备份脚本，增加少量共享状态组件、错误翻译、试用清单和包体积门禁。风险低，能长期防止同类问题反复出现。

### 方案 C：引入完整浏览器自动化框架

覆盖更深，但需要新增依赖、浏览器运行时和维护成本。当前小范围本地试用没有必要，本轮不采用。真实交互仍使用 Tabbit 做多角色验收，代码仓库内用契约测试锁住关键行为。

## 范围与边界

- 只修改 `/Users/yenns/Documents/新版招聘/zhipin-mvp` 当前本地版本。
- 当前前端仅为 `readdy-frontend`；不启动或修改旧前端。
- 人才地图保持原样。
- 不新增业务页面，不改变接口和数据库结构。
- 不清理、不覆盖当前本地数据库；恢复能力只提供经过校验的说明和安全入口。
- 不推送、不部署、不切换分支。
- 模型解析、外部消息、外部日历和公司接口不在范围内。

## 第一批：状态反馈和无障碍收口

### 共享页面状态

增加一个现有视觉风格的共享状态组件，覆盖三种情况：

1. 加载中：说明正在读取什么。
2. 空数据：说明为什么为空，并给出可执行的下一步。
3. 加载失败：使用大白话说明失败，并提供“重新加载”。

组件只负责展示和调用已有回调，不请求数据、不保存状态。招聘需求、面试管理、Offer、面试官需求、面试官筛选和我的面试等核心工作页按需要复用。

### 错误翻译

增加统一错误翻译函数。网络错误、HTTP 状态码、技术异常等不得原样展示给业务用户；后端已经返回的清晰中文业务提示继续保留。所有错误状态必须保留原地重试入口。

### 关闭按钮

所有本轮涉及的弹窗和抽屉图标关闭按钮必须有可读名称，至少包含 `aria-label`，并继续复用现有弹层生命周期，确保 Escape、焦点恢复和背景滚动行为不回退。

## 第二批：测试数据和试用过程收口

### 测试数据规则

不批量修改或删除现有记录。新增试用说明，要求新建记录统一带“验收测试”前缀，并明确真实隐私数据不得进入本地库。候选人已有的本地演示标记继续保留。

### 可恢复试用

复用现有 `backup_pilot_data.py` 和 `restore_pilot_data.py`，不再造第二套备份实现。试用前创建包含数据库、附件和校验清单的完整快照；恢复前必须先停服务、运行 dry-run、核对目标路径，再由用户明确决定是否执行恢复。本轮不会自动恢复或覆盖当前数据。

### 角色验收清单

在现有试用文档中补充可勾选清单，按招聘专员、一面、二面、负责人和管理员拆分。每个角色都包含正常路径、切页返回、弹层关闭、空状态和错误恢复检查，反馈格式继续使用测试编号，不记录真实简历信息。

## 第三批：自动防回归和性能收口

### 核心流程契约

增加轻量 Node 契约测试，锁定：

- 核心工作页使用统一状态组件；
- 错误状态有大白话和重试；
- 图标关闭按钮有可读名称；
- 试用说明包含五角色流程、数据前缀、备份和恢复安全要求；
- 不修改人才地图，不新增业务路由。

### 包体积门禁

在正式构建后检查构建产物：首屏主包不得重新膨胀到优化前水平，大页面独立分包不得无上限增长。门禁只读取构建产物，不改变打包逻辑。阈值以当前已验证结果留出合理余量，避免因为哈希文件名或很小波动误报。

### 真实界面验收

自动测试通过后，在 Tabbit 中按管理员、招聘专员、一面、二面和负责人检查核心页面。只做读取、切页、筛选和开关详情，不提交淘汰、评价、Offer 或其他高影响业务动作。

## 测试策略

所有行为改动按测试驱动执行：先新增会失败的契约测试，再做最小实现，然后运行目标测试。三批全部完成后运行：

1. 后端全量测试；
2. 前端全部 Node 契约测试；
3. TypeScript 类型检查；
4. ESLint；
5. Vite 正式构建和包体积门禁；
6. 依赖安全和数据库迁移检查；
7. Tabbit 多角色只读验收；
8. 端口、进程目录和 Git 状态检查。

## 风险与控制

| 风险 | 等级 | 控制方式 |
|---|---|---|
| 共享状态组件替换时遗漏原有动作 | 中 | 组件只接收已有回调，逐页契约测试后再替换 |
| 错误翻译遮住有用业务信息 | 中 | 仅替换明确的技术错误，清晰中文原样保留 |
| 恢复操作覆盖当前试用数据 | 高 | 本轮不执行恢复；文档要求停服务、dry-run 和用户确认 |
| 包体积阈值过紧造成误报 | 低 | 以当前构建留出余量，并按入口包和最大路由包分别检查 |
| 自动测试无法代替真实交互 | 低 | 最后仍使用 Tabbit 完成五角色只读验收 |

## 完成标准

- 核心工作页的加载、空数据和错误状态表达一致，错误可重试。
- 本轮涉及的图标关闭按钮都有可读名称。
- 同事能按清单跑完整流程，并知道如何创建快照和安全恢复。
- 自动测试能阻止状态组件、关闭按钮、试用文档和包体积回退。
- 全量门禁和 Tabbit 多角色验收通过。
- 人才地图、数据库业务数据和外部接口未改动。
