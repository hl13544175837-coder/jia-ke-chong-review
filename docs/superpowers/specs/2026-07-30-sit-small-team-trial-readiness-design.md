# Test 小范围同事试用收口设计

## 目标

让同事通过公司工号登录公司 Test 环境，分别以招聘专员、一面面试官、二面面试官、经理和总监角色跑通招聘需求、简历入库、人工补录、筛选、面试、改约、反馈、Offer、人才池和入职流程。简历模型解析明确不属于本轮范围，系统不得反复调用不可用模型或显示 403 技术错误。

## 范围

- 保留公司 OAuth 登录，不增加第二套登录页，不部署本地登录桥。
- 用环境变量按公司工号映射试用角色；未映射工号默认招聘专员，避免默认管理员。
- Test 环境显式关闭简历模型解析。上传文件仍入库并保留原件，页面引导招聘专员手动补录基础信息。
- 使用持久数据库和附件目录；部署时单实例升级数据库到 `20260730_13`。
- 发布提交排除本地数据库、密钥、飞书画板产物和验收截图。
- 不新增业务页面，不改变现有招聘状态机，不接入外部模型、邮件、短信或日历接口。

## 公司工号角色方案

前后端共同读取 `EMP001:admin,EMP002:recruiter` 形式的工号角色映射。前端用映射决定菜单和页面；后端用同一映射决定权限和审计身份。允许角色为 `admin`、`manager`、`recruiter`、`interviewer`、`hr_director`。

映射不存在或格式错误时采用最小权限：默认 `recruiter`。映射只在明确的 RC/SIT 网关模式下使用，不改变 GA/生产 JWT 登录逻辑。已由网关自动创建的试用用户在映射明确变化时同步角色，确保重新部署后角色配置可纠正。

## 关闭模型后的简历路径

新增 `RESUME_AI_ENABLED` 环境开关，默认保持 `true`，避免影响其他环境。Test 小范围试用模板设置为 `false`。

关闭后上传流程不调用模型：

1. 校验并保存 PDF/DOCX/ZIP 原文件。
2. 创建候选人记录，状态进入“待手动补录”。
3. 返回大白话提示：“当前测试环境未启用模型解析，原始简历已保留，请手动补录基础信息。”
4. 用户可在现有候选人详情中打开编辑入口，填写姓名、电话、岗位、经历和技能。
5. 补录保存后继续筛选和后续招聘流程。

模型关闭不视为系统故障，不记录外部 403，不自动重试模型。

## Test 环境与发布保护

- 提供小团队 Test 环境变量模板，明确数据库、附件、固定密钥、OAuth、工号角色映射和模型关闭配置。
- Readdy 前端镜像默认角色由 `admin` 改为 `recruiter`，并支持从 CI 构建变量注入工号角色映射。
- `.gitignore` 和 `.dockerignore` 排除 `diagrams/`、本地验收图片、运行数据库和密钥文件。
- 部署文档更新当前迁移 head、单实例迁移、空库账号初始化和 Libra/API 构建步骤。
- Git 推送只面向 `https://git.ymdd.tech/cfpd/zhipin-mvp.git` 的 `test`；本轮开发完成后先展示提交清单，不自动 commit 或 push。

## 验收标准

- 未映射公司工号不会获得管理员权限。
- 指定工号在前后端得到一致角色。
- `RESUME_AI_ENABLED=false` 时模型解析器零调用，原件和候选人记录保留，并出现手动补录提示。
- 人工补录后可以继续完整招聘流程。
- 数据库迁移 head 为 `20260730_13`，Test 数据和附件重启后不丢。
- 后端全量测试、前端 Node 测试、类型检查、lint、生产构建和部署门禁全部通过。

## 风险

- 中：公司网关必须可信地注入工号；若允许客户端伪造 `X-Emp-Code`，角色映射仍可能被冒用，Test 网关必须覆盖或清洗该请求头。
- 中：Test 数据库升级前必须备份，并避免多个新后端副本并发执行迁移。
- 低：模型关闭后需要招聘专员手动补录，流程可用但录入工作量增加。
- 低：角色映射是 Test 配置，新增同事时需要补充工号并重新构建前端、更新后端环境。
