# 结构化简历全宽布局设计

## 背景

候选人详情抽屉最宽可达 1280px，但结构化简历在宽屏下固定分为三栏：工作、项目等长内容占左侧三分之二，基本信息、教育、技能等短内容占右侧三分之一。右侧内容结束后会留下大面积空白，同时长工作经历被限制在较窄区域。

## 目标

让结构化简历充分使用抽屉宽度：先快速浏览候选人概览，再用整行宽度阅读工作经历和项目经历，不出现贯穿页面的空白侧栏。

## 已确认方案 A

- 求职目标、个人概况、教育经历、专业技能、证书与语言等短内容放在顶部概览区。
- 顶部概览区使用响应式卡片网格；宽屏横向排列，窄屏自动减少列数。
- 工作经历、项目经历和其他长内容放在概览区下方，按原顺序纵向排列并占满整行。
- 已发布的工作经历卡片样式保持不变：公司、岗位和任职时间仍在同一卡片头部，职责成果在下方。
- 如果简历只有长内容或只有短内容，直接按现有顺序全宽展示，不生成空区域。

## 组件边界

- 只调整 `StructuredResumeView` 的段落编排，不修改候选人详情抽屉宽度。
- 不修改 `buildResumeSections` 的数据分组结果，不改变后端结构化简历数据。
- 复用现有 `Section`、`WorkHistoryValue` 和通用字段渲染组件。
- 顶部概览区和下方长内容区使用明确的 `data-ui` 标记，便于回归测试和浏览器验收。

## 响应式规则

- 小屏：概览区单列，所有内容自然换行。
- 中等屏：概览区两列。
- 大屏：概览区根据内容使用两至三列，但下方长内容始终全宽。
- 公司名和长文本允许换行，不横向撑破抽屉。

## 验收标准

1. 张征的工作经历区域占满结构化简历可用宽度。
2. 页面右侧不再因固定侧栏产生贯穿工作经历区域的大块空白。
3. 顶部仍能看到求职目标、概况、教育和技能等信息。
4. 工作经历卡片继续把公司、岗位和任职时间放在同一头部。
5. 只有短内容、只有长内容、字段缺失的简历均能正常展示。
6. 前端契约测试、类型检查、Lint、生产构建和 SIT 浏览器验收通过。

## 非目标

- 不改候选人详情抽屉整体宽度。
- 不修改简历解析、编辑、版本、更换、预览或下载逻辑。
- 不调整候选人列表、面试信息和面试评价页签。
