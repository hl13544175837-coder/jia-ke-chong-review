# 月度招聘漏斗优化设计

## 目标

在不改动其他核心组件的前提下，把工作台中口径混乱、位置重复的招聘漏斗改成跟随“月份 + 招聘专员”的真实月度漏斗。

## 已确认的页面结构

1. 删除工作台顶部的“总体漏斗”。
2. 删除岗位进展右侧重复的“阶段概况”，保留“等待他人”。
3. 保留底部“数据看板”的月份、招聘专员、刷新、岗位明细和本月合计。
4. 在数据看板内按“筛选条件 → 当月招聘漏斗 → 月份合计 → 岗位明细”的顺序展示。

## 统计口径

- 范围：所选招聘专员负责、在所选自然月发生招聘推进的需求。
- 去重：同一需求下，同一候选人在同一阶段只计算一次；同一候选人参与不同需求时分别计算。
- 阶段：简历库、初筛、业务筛选、面试、Offer、入职。
- 连续性：候选人当月到达较后阶段时，视为已经走过之前阶段，避免出现“业务筛选 0 人、面试 7 人”这类倒挂。
- 转化率：后一阶段人数 ÷ 前一阶段人数；前一阶段为 0 时显示“—”。
- 演示数据：使用现有演示流程计算出非零、从前到后不增加的漏斗，确保常规演示可正常计算转化率。

## 交互

- 切换月份或招聘专员后，漏斗、月份合计和岗位明细一起刷新。
- 漏斗阶段保持可点击，并沿用现有页面跳转规则。
- 真实空数据仍有安全兜底，不伪造业务数据。

## 不在本次范围

- 不调整工作台其他卡片、按钮、颜色和文案。
- 不修改招聘需求、简历库、面试管理、Offer、人才地图页面。
- 不更换技术栈，不改接口地址和权限规则。

## 验收标准

1. 工作台只保留一套招聘漏斗，且位于月度数据看板内。
2. 漏斗与月份和招聘专员联动。
3. 各阶段人数从前到后不增加，常规演示数据每一阶段均可计算转化率。
4. 分母为 0 时页面显示“—”，不显示误导性的 0%。
5. 原有月份合计和岗位明细仍可用。
6. 相关前后端测试、类型检查、代码检查和正式构建通过。
