# Test 验收数据与招聘需求输入优化设计

## 目标

本次同时解决两个问题：

1. 给 Test/SIT 增加一套可重复生成、不会清空现有数据的虚构验收数据，方便验证招聘需求、候选人筛选、面试、Offer 和数据看板。
2. 允许面试官提交自定义新岗位，并允许招聘专员填写固定列表之外的部门和招聘地点。

## 界面设计

### 面试官提交自定义岗位

“岗位模板”保留现有模板选择，并增加“自定义新岗位”选项。

- 选择现有模板时，继续自动带出岗位名称、部门、城市、JD 和面试关注点。
- 选择“自定义新岗位”时，显示必填的岗位名称输入框；部门、城市、JD 和面试关注点由面试官填写。
- 提交时，后端在同一个事务中创建岗位资料和待审核招聘需求。任一步失败，两者都不保存，避免留下半条数据。
- 招聘需求仍保持“待审核”，后续由招聘专员、招聘主管或管理员审批。
- 已驳回需求继续复用原岗位资料重新提交，本次不增加“重新提交时更换岗位”的能力。

### 招聘专员填写部门

“所属部门”从只能选择的下拉框改为可输入文本，并保留现有六个部门作为快捷建议。用户既可以点击建议，也可以输入新部门。

### 招聘专员填写招聘地点

原来的“省份下拉 + 城市下拉”合并为可输入的“招聘地点”。常用国内城市继续作为快捷建议，但用户也可以填写海外城市、国家/城市组合、“海外”或“远程办公”等文本。后端继续使用现有城市字段保存完整招聘地点，不新增数据库字段或迁移。

## Test/SIT 验收数据

新增一套独立的、幂等的验收数据脚本。脚本只处理带固定验收标记的数据，不复用或修改现有候选人。

固定标记：

- 需求编号使用 `ACCEPTANCE-TEST-` 前缀。
- 候选人姓名使用 `验收测试-` 前缀。
- 虚构邮箱使用 `example.com`，电话使用脱敏格式。

覆盖场景：

- 面试官本人提交的待审核需求。
- 已审核并处于招聘中的需求。
- 待业务筛选、筛选已通过、待补充和不合适的候选人。
- 待确认、即将开始、待反馈和已完成的面试任务。
- 草稿、审批中、待发送、待回复、待入职和已入职的 Offer。
- 能被工作台和数据看板统计、下钻的流程阶段。

## 安全规则

- 默认只输出预览，不写数据库；必须显式传入 `--apply` 才写入。
- 只允许 RC 且开启可丢弃 SIT 标记的环境执行；GA/生产直接拒绝。
- 不执行全表删除，不调用 `seed_dev.py`，不修改没有验收标记的记录。
- 以固定需求编号和候选人验收标记查找数据，重复执行只刷新同一套记录。
- 发现同一验收标记对应多条记录时停止执行，不自动猜测或合并。
- 第一次执行后再次执行，记录总数必须保持不变。

## 验证

自动验证：

- 后端测试覆盖自定义岗位创建、事务回滚和面试官待审核状态。
- 前端测试覆盖“自定义新岗位”输入与自定义部门输入。
- 前端测试覆盖招聘地点可输入海外或远程文本，且常用国内城市仍可作为建议。
- 验收数据脚本测试覆盖默认预览、环境阻断、首次新增和重复执行不重复。
- 运行后端测试、前端合同测试、类型检查、代码检查和生产构建。

Test/SIT 现场验证：

- 脚本先预览，再执行两次，第二次不得增加记录。
- 李四能看到待筛选和我的面试测试任务。
- 招聘端能看到需求、候选人阶段和 Offer 测试数据。
- 数据看板能统计并下钻到带“验收测试”标记的数据。
- 原有非验收数据的数量和内容不被脚本修改。
