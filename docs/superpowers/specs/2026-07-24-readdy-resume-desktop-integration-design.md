# Readdy 桌面端交互与图片简历融合设计

## 1. 目标

在不修改现有公司仓库和当前运行环境的前提下，建立一套独立、可运行、可整目录删除的智聘演示产品。产品以公司 GitLab `test` 分支的真实业务结构为底座，吸收 Readdy 导出源码中的桌面端页面和交互，并完整迁入 GitHub 最新图片简历识别能力。

本轮交付重点是可供少量公司同事在内网电脑浏览和操作的产品演示。真实业务接口由后续研发接入，本轮只保留稳定、清晰的数据契约和替换入口。

## 2. 来源与优先级

1. 公司候选代码：`codex/readdy-test-product`，提供业务模型、角色、权限、后端和已有 Readdy 迁移成果。
2. Readdy 导出包：`project-12214982 (1).zip`，提供完整桌面端布局、页面、按钮、弹窗、抽屉和演示数据。
3. GitHub 图片简历版本：`codex/target-mode-stage1-modules` 的 `de12163` / `760593a`，提供 JPG、JPEG、PNG、WebP、GIF 和 ZIP 内图片简历识别。

冲突时按以下顺序决策：公司业务语义和权限优先于 Readdy 演示语义；Readdy 交互完整性优先于旧页面的静态占位；GitHub 图片简历安全校验完整保留。

## 5. 前端架构

### 5.1 页面与组件

保留当前公司项目 React 18、React Router 6、Tailwind 和现有应用壳，按模块吸收 Readdy 交互。不得直接用 Readdy 的 React 19/Router 7 工程覆盖公司前端。

共享交互优先沉淀为已有或新增的通用组件：

- 右侧详情抽屉
- 模态框和确认框
- 分段控制、筛选器和分页
- 加载、空数据、错误、禁用和成功提示
- 表格行下钻和统计卡下钻
- 文件拖放、文件列表和上传结果

### 5.2 数据适配层

页面不得直接导入 Readdy 的 `src/mocks/*`。每个业务模块继续通过当前类型化服务接口读取和写入数据：

```text
页面/组件 -> 模块服务接口 -> 隔离本地 Flask + 种子数据（本轮）
                         -> 公司正式服务配置（后续研发替换）
```

本轮不新增公司正式业务接口，也不接生产服务。已有接口在独立数据库和独立上传目录上运行；后续研发可保持页面和类型不变，只替换服务配置或补齐接口。确实没有后端契约的演示操作使用当前浏览器会话内状态，刷新页面后允许恢复初始状态。

## 6. 交互规则

所有可见按钮必须满足以下一种状态，禁止无响应：

1. 执行完整的前端交互，例如打开抽屉、弹窗、菜单、筛选、排序、分页或切换视图。
2. 通过隔离本地接口或会话内演示状态完成操作，更新页面并显示成功或失败提示。
3. 后续真实系统才能完成且不适合模拟的操作，必须明确禁用并给出简短原因。

关键规则：

- 表格行、姓名、统计卡和阶段数字提供稳定下钻。
- 删除、淘汰、拒绝、撤回等高影响操作先确认再更新状态。
- 表单必须校验必填项；提交中防重复点击；失败后保留用户输入并可重试。
- 弹窗、抽屉支持关闭按钮、遮罩和 `Esc`；关闭后焦点返回触发按钮。
- 切换岗位、需求或角色时清理上一上下文，避免详情串数据。
- 所有成功操作均给出可见反馈，所有错误均给出原因和下一步。

## 7. 图片简历

完整迁入 GitHub 图片简历能力：

- 支持 JPG、JPEG、PNG、WebP、GIF，以及 ZIP 内的图片简历。
- 保留扩展名、文件签名、真实图片格式、尺寸、像素、体积、压缩包条目和路径穿越校验。
- 保留图片归一化、Base64 视觉模型请求、结构化结果清洗和原文件预览。
- 模型地址、模型名、API Key 和超时通过环境变量注入，不写入代码或文档。
- 未配置模型时，上传页面仍可选择和校验图片，并明确显示“识别服务未配置”，不能伪装识别成功。
- 自动化测试使用假模型响应，不需要真实密钥。

## 8. 角色与登录

演示环境保留 recruiter、manager、admin、interviewer 四角色和路由守卫。提供固定演示账号，登录后根据账号进入对应工作区；越权路由显示明确拒绝页，不泄露目标页面数据。

演示身份只用于本地/内网产品验收。正式网关接入点和当前后端身份类型保留，后续研发可替换演示认证适配器。

## 9. 桌面端验收

只对电脑端进行专项验收：

- `1366 x 768`
- `1440 x 900`
- `1920 x 1080`

每个核心页面检查：导航可达、文本不溢出、按钮不重叠、抽屉/弹窗在视口内、表格可扫描、加载/空/错/禁用状态完整、控制台无未处理错误。

测试门禁包括：

- 前端合同测试、类型检查、Lint 和生产构建
- 后端图片简历、安全与相关回归测试
- 静态按钮审计：发现无 handler、无提交语义且非明确禁用的按钮即失败
- 浏览器逐页主流程和关键按钮验收
