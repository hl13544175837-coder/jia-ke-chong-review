# 招聘流程总览页设计

## 目标

新增一个独立、只读的“招聘流程总览”页，供招聘专员和管理层共同查看招聘全链路。页面以飞书《智聘招聘主流程与接口全景图》为唯一展示基准，不调用接口，也不改变业务数据。

## 展示口径

- 页面顶部明确说明：接口准备情况来自飞书基准图，仅作流程说明，不代表当前页面已调用真实接口。
- 接口状态统一使用四种标签：`后端已实现`、`前后端已串联`、`外部待对接`、`已联调验收`。
- 不依据当前本地代码重新判断或覆盖飞书图中的接口准备情况。

## 页面结构

```text
招聘流程总览
├─ 页面说明与接口状态图例
└─ 连续招聘流程（11 步）
   ├─ 需求启动：创建并提交招聘需求 → 审核需求并生效
   ├─ 候选人筛选：导入简历并关联需求 → 初筛并推送业务审核 → 业务初筛并返回结论
   ├─ 面试决策：创建面试安排 → 面试进行并确认任务状态 → 主面试官提交本轮评价 → HR 确认本轮处理结果
   ├─ Offer 管理：Offer 拟定、审批、发放与答复
   └─ 入职闭环：确认实际入职并结算岗位缺口
```

桌面端将以四列泳道呈现每一步：

1. **状态流转**：步骤号、标题、可进入状态与结果。
2. **主责角色**：用人部门、招聘专员、业务面试官、主面试官或系统。
3. **动作说明**：该角色在这一步完成的业务动作与约束。
4. **接口准备情况**：接口名称与飞书图中的准备状态标签。

移动端将同一内容改为按步骤排列的卡片，保留所有字段，避免四列压缩造成无法阅读。

## 状态与分支

主链路保持从第 1 步连续到第 11 步。需要明确绘制下列分支：

- 需求审核可通过、驳回或补充信息；通过后才允许进入招聘。
- 业务筛选通过后进入面试安排；不通过则结束。
- 面试可取消、改约或重新排期；改约或加面时回到面试安排。
- HR 根据本轮评价决定加面、淘汰或进入 Offer；淘汰时结束。
- Offer 状态为草稿、待审、已批准、已发送、接受/拒绝；拒绝、过期或撤回会释放名额。
- 入职确认后标记 `onboarded`，岗位缺口减一；达到 HC 仅提示“可关闭”，由 HR 手动关闭需求。

## 实现边界

- 新增一个路由页面和对应导航入口。
- 采用本地、类型化的流程配置作为单一数据来源；不发起网络请求。
- 页面不提供跳转、编辑、筛选或状态修改功能。
- 不改动现有需求、简历、面试、Offer 等业务页面及其数据逻辑。

## 验收与验证

- 自动检查流程配置中存在 11 个步骤、5 个分组、4 类接口状态和关键分支文本。
- 前端构建通过。
- 使用本地账号进入系统后，确认总览页在桌面宽度和手机宽度均能完整阅读，且没有横向内容截断或重叠。
