# 筛选布局一致性设计（紧凑可收缩版）

## 目标与范围

本轮只整改现有页面中的筛选区域，不做全角色、全页面视觉重构。检查侧边栏可进入的业务页面：页面存在搜索、范围切换、条件筛选或表头筛选时，按本设计统一；没有筛选的页面不改；与筛选无关的业务流程、权限、BI 口径、技术债收口路线和后端 owner 不改。

候选人库是本轮首个完整落地页，也是其他筛选页的基准。其他页面只复用同一布局与去重规则，不照搬候选人专属字段。

## 已确认的交互规则

### 1. 固定上下层级

- 表格列能自然承载、且用户经常使用的条件，保留在对应表头。
- 不属于单一可见列、需要较大控件或使用频率较低的条件，放在表格上方。
- 同一个条件不得同时出现在顶部和表头；已有重复入口必须删除。
- 每个已有筛选页面统一采用“普通筛选在上、绿色状态分类在下、列表或表格最后”的顺序。搜索、部门、城市、负责人、岗位和日期等普通筛选不得放到绿色状态分类下面，也不得塞进列表或表格卡片内部。
- 绿色状态分类始终直接显示，不参与普通筛选区域的展开或收起。候选人库保留“全部候选人、招聘流程中、公司人才库、我的收藏”四个既有产品范围；招聘需求、面试、Offer 等页面保留各自现有状态分类，不改变业务含义。
- 页面没有绿色状态分类时，只统一普通筛选位于列表或表格上方，不为了视觉一致新增虚假的状态分类。

页面的标准结构为：

```text
[搜索] [部门] [城市] [负责人] [岗位] [开始日期] [结束日期] [收起筛选]

[全部] [待审核] [招聘中] [已完成] [已停止]
────────────────────────────────────────
列表 / 表格
```

普通筛选收起后，绿色状态分类仍固定显示：

```text
[展开筛选]

[全部] [待审核] [招聘中] [已完成] [已停止]
────────────────────────────────────────
列表 / 表格
```

### 2. 普通筛选整体收缩

- 收起和展开只作用于上方整组普通筛选，不逐项制造“更多筛选”入口。
- 默认进入页面时普通筛选展开；点击“收起筛选”后隐藏整组普通筛选控件，只保留一个紧凑的“展开筛选”入口。
- 收起不会清除已经选择的条件。存在有效条件时，“展开筛选”入口显示有效条件数量，帮助用户理解列表为何发生变化。
- 再次展开后恢复全部普通筛选控件和原有选中值。绿色状态分类在两个状态下都不移动、不隐藏、不需要再次展开。
- 展开/收起是页面展示状态，不改变 URL、服务端筛选参数、分页和业务数据。

### 3. 统一紧凑尺寸与间距

- 普通筛选不再使用拉伸到整行的等分网格，改为从左到右的紧凑工具栏，空间不足时自然换行。
- 桌面端所有普通筛选控件统一使用 `160px` 宽、`36px` 高、相同圆角，不因页面剩余空间变长；搜索框、下拉框、日期框、排序和重置入口全部遵守同一尺寸，不只整改搜索框。
- 普通筛选控件的视觉高度与绿色状态分类一致；绿色状态分类保留现有内容宽度和业务文案，不把状态分类强行拉成长输入框。
- 搜索框使用简短占位文案，完整搜索范围通过 `aria-label` 和页面说明保留，避免为了塞入长提示文字重新拉长控件。
- 控件横向间距、换行后的纵向间距、普通筛选到状态分类、状态分类到列表或表格的间距统一使用 `8px`。
- 普通筛选区不再使用占据整块页面的大面积浅色背景或双列大卡片，只保留必要的轻量容器和清楚的展开/收起入口。
- 小于 `640px` 的窄屏允许控件变为单列全宽，保证可操作性；桌面端不得因为响应式规则重新拉伸为半屏或整屏宽。

### 4. 候选人库字段归位

顶部普通筛选按紧凑工具栏排列：

1. 精确搜索；
2. 招聘需求；
3. 入库开始日期；
4. 入库结束日期；
5. 来源渠道；
6. 解析状态；
7. 排序方式。

表头保留高频筛选：

- 流程状态；
- 学历；
- 意向城市；
- 当前阶段。

“学历”和“意向城市”必须拆成两个独立列和两个独立筛选。入库日期仍作为表格列展示，但筛选改为顶部的开始、结束日期，结束日期包含所选当天。

“流程状态”只回答候选人现在是否处于活动流程或哪一种终态；“当前阶段”只在招聘流程中进一步筛选待筛选、AI 初筛、业务待反馈、面试中、Offer 等活动阶段。当前阶段下拉不再重复提供未进入流程、淘汰、已入职和已转出。

“核心技能”列、技能关键词筛选和最低技能分筛选本期从候选人库界面隐藏，明确进入二期；后端已有字段和接口能力不删除，避免破坏既有调用链。

### 5. 流程状态不能丢失历史语义

候选人可能处于招聘流程中、从未进入流程、当前已淘汰，也可能已有终态。页面不得把“未在招聘流程中”全部显示为同一种状态。

服务端基于既有 Demand Flow 和 PipelineStage 事实返回只读派生状态，不新增数据库字段，不让前端猜业务真相：

- `in_pipeline`：存在活动招聘流程；
- `never_entered`：没有任何招聘流程历史；
- `rejected`：当前无活动流程，最新有效状态为淘汰；
- `onboarded`：当前无活动流程，最新有效状态为已入职；
- `transferred`：当前无活动流程，最新有效状态为已转出。

若候选人当前重新进入流程，但历史上曾被淘汰，当前状态仍显示“招聘流程中”，同时通过独立的“曾淘汰”历史标记保留事实，不能把当前状态错误显示为淘汰。

表格中的“流程状态”展示上述派生状态；“当前阶段”对活动流程展示详细阶段，对未进入流程和终态显示 `—`，从而避免两个列重复表达同一件事。

现有“公司人才库”范围继续遵守 PRD：从未进入流程或最新状态为已淘汰的候选人可进入人才库；已入职和仅有已转出终态的档案不进入。新增展示和筛选不得改变该范围口径。

### 6. 点击信息快速筛选

表格中的流程状态、学历、意向城市、当前阶段等已有对应筛选的信息可点击。点击后复用同一个筛选状态和 URL 参数，刷新服务端分页结果；不能另建一套仅过滤当前页的逻辑。当前选中条件必须可见、可单独取消、可一键清空，并保留键盘操作和清楚的可访问名称。

## 数据与接口

- `GET /api/candidates` 新增可选入库日期参数 `created_from`、`created_to`，格式为 `YYYY-MM-DD`；非法日期或开始晚于结束返回 `400`；结束日期按包含当天处理。
- 在保持现有 `pipeline_status=in_pipeline|not_in_pipeline` 兼容的前提下，增加精确状态筛选值 `never_entered|rejected|onboarded|transferred`。
- 候选人列表项增加只读 `pipeline_state` 和 `has_rejected_history`。派生逻辑由后端集中实现，前端只展示和触发筛选。
- 技能相关 API 参数继续兼容，但本期候选人库 UI 不发送这些条件。

## 组件边界

- 抽取一个统一的可收缩筛选工具栏，只负责普通筛选的上下位置、紧凑宽高、自动换行、展开/收起、有效条件数量和统一间距，不承载候选人、需求、面试或 Offer 的业务语义。
- 绿色状态分类继续由现有 `WorkspaceTabs` 承载，并由各页面放在统一筛选工具栏之后。可收缩工具栏不能包住、移动或隐藏 `WorkspaceTabs`。
- 候选人筛选状态继续由现有 filter controller 管理；新增日期与精确流程状态进入同一 URL 同步、重置和分页归零链路。
- 表头筛选继续使用既有可关闭浮层组件；删除重复内容并把学历、城市拆开。
- 后端状态派生进入候选人 API 的集中辅助函数，不在 React 组件中散落判断。

## 异常与边界

- 只填写开始或结束日期时允许单边筛选。
- 日期非法或区间反转时，后端给明确中文错误；前端保留用户输入并提示，不静默改值。
- 没有流程历史时显示“未进入流程”，不显示空横线。
- 当前活动流程优先于历史淘汰记录；历史淘汰通过独立标记表达。
- 点击单元格筛选后回到第一页并清空跨结果选择，避免批量操作作用到不可见候选人。
- 收起普通筛选时已有条件继续生效；“展开筛选”显示条件数量，不能让用户误以为筛选已经清空。
- 移动端和窄屏允许表格横向滚动，顶部普通筛选按一列堆叠，不压缩为不可操作的小控件；绿色状态分类继续横向滚动或换行。

## 验收

- 候选人库、招聘需求、面试管理、Offer 以及业务负责人已有筛选页均为“普通筛选在上、绿色状态分类在下、列表或表格最后”，不再各自采用不同位置。
- 桌面端所有普通筛选控件为 `160px × 36px`，间距为 `8px`，不再出现半屏或整屏长框；搜索、下拉、日期、排序和重置一致执行。
- 普通筛选可以整组收起和重新展开，收起后条件继续生效且能看到有效条件数量；绿色状态分类始终显示，不需要展开。
- 顶部和表头不存在同义重复筛选；学历与意向城市分开。
- 日期区间能正确筛选起止边界，结束日期包含当天，并在服务端分页前生效。
- 招聘流程中、未进入流程、已淘汰、已入职、已转出显示和筛选准确；重新进入流程且曾淘汰的候选人不被误判。
- 核心技能、技能关键词和最低技能分在本期候选人库 UI 不显示。
- 具备筛选含义的表格信息可点击，行为与原筛选入口一致。
- 审查其他有筛选的业务页面，只统一布局、间距和重复入口，不修改无关业务语义。
- 前端相关测试、后端候选人分页筛选测试、TypeScript 检查和构建通过。

## 不在本轮范围

- 删除技能数据、标签表或技能相关后端接口；
- 重做导航、角色页面或无筛选页面；
- 改变公司人才库、招聘阶段、Demand 归属、权限、BI、AI 写操作或部署路线；
- 把所有页面强制改成同一组筛选字段。
