# 面试管理折中版界面设计

## 目标

在不改变现有真实面试流程、接口和技术栈的前提下，把旧版有价值的信息密度、筛选和日历能力迁回当前可用页面，同时保留当前版清楚的状态按钮和完整操作闭环。

最终体验需要同时满足：

- 默认页面干净，不恢复旧版多排筛选、多按钮拥挤的状态。
- 候选人很多时，招聘专员仍能快速找到目标面试任务。
- 所有已经跑通的安排、改期、取消、确认已面试、催反馈、查看反馈、下一轮、增加面试官、进入 Offer 和淘汰操作继续使用真实数据。
- 默认使用列表，按需切换日历。

## 已确认的视觉方向

采用“平衡双行列表 + 单排工具栏 + 隐藏式筛选”。

页面顶部保持一条水平工具栏：左侧是“全部、待安排、已安排、待反馈、已完成”状态入口；右侧依次是搜索框、筛选按钮、结果数量和“列表 / 日历”切换。筛选条件默认不展示，点击筛选按钮后在按钮下方打开悬浮浮层，不新增第二排工具栏，也不把列表向下推。

## 页面结构

### 标题区

- 保留“面试管理”标题和简短说明。
- 刷新按钮放在标题区右侧。
- 成功和失败提示继续使用当前页面已有反馈方式。

### 单排工具栏

- 左侧：状态标签及各状态数量。
- 右侧：关键词搜索、筛选入口、筛选后结果数量、列表/日历切换。
- 工具栏在桌面宽度下必须保持一整排，视觉左右平衡。
- 窄屏时允许搜索框缩短，并优先隐藏低优先级文字；不能把所有按钮机械地挤成两排。

### 隐藏式筛选

筛选浮层包含六项：

- 岗位
- 面试官
- 日期范围
- 面试轮次
- 城市
- 部门

筛选规则：

- 默认关闭。
- 点击“筛选”打开悬浮浮层，再次点击、点击外部或按 Esc 关闭。
- 六项采用对称网格排列，不形成上下两排常驻按钮。
- 支持单项或多项组合筛选。
- 筛选按钮用数字角标提示已选条件数量。
- 浮层提供“重置全部”“取消”“查看 N 条结果”。
- 状态标签和关键词搜索与浮层条件共同生效。

## 列表设计

采用平衡双行表格，一屏约显示 7 至 9 条，列为：

1. 候选人 / 应聘岗位：第一行姓名，第二行岗位和部门。
2. 面试轮次。
3. 面试安排：时间；未安排时明确显示“时间待安排”。
4. 面试官。
5. 状态。
6. 操作。

操作区只展示当前最重要的一个主操作；需要同时保留的次操作最多显示一个，其余放入“更多”菜单，避免旧版一行出现三至四个彩色按钮。

各状态主要操作：

- 待安排：安排面试。
- 已安排且未开始：调整安排；取消等低频动作进入更多菜单。
- 已安排且时间已到：确认已面试为主操作，调整安排为次操作。
- 待反馈：催反馈。
- 已完成：查看反馈。

点击候选人区域继续打开当前真实详情侧栏。反馈后的“下一轮、增加面试官、进入 Offer、淘汰”保留在详情侧栏，不塞回列表行。

## 日历视图

- 默认进入列表视图，用户可在同一工具栏切换日历。
- 日历使用真实 `InterviewManagementRow` 数据，不复用旧 Mock 数据。
- 仅有明确面试时间的任务进入日期格；待安排任务在日历上方以待安排提示区展示，避免被丢失。
- 点击日历任务打开与列表相同的详情侧栏。
- 搜索、状态和筛选条件对列表、日历同时生效。

## 数据与组件边界

- 保持现有 `interviewsApi.listManagementRows()` 和真实工作流接口不变。
- 前端筛选基于已经返回的 `job_title`、`job_city`、`job_department`、`round_sequence`、`interviewer_id`、`scheduled_at` 等字段完成，不新增后端接口。
- 将工具栏、筛选浮层、平衡列表和真实日历拆成职责清晰的小组件，页面继续负责加载数据、组合筛选条件和调用现有动作。
- 旧版 `dashboard/interviews` 仍属于 Mock 实现，不能直接恢复路由或重新接入；只迁移经过确认的布局思想。

## 异常与空状态

- 加载、加载失败、无结果继续沿用当前真实页面处理。
- 筛选后无结果时显示“没有符合当前条件的面试任务”，并提供重置筛选入口。
- 日期、面试官或部门缺失时显示明确占位文案，不留空白。
- 操作请求失败时保留筛选和当前视图，不清空用户上下文。

## 验收标准

- 桌面端工具栏正常状态下只有一排。
- 筛选默认隐藏，浮层不会推动列表位置。
- 关键词、状态、岗位、面试官、日期、轮次、城市和部门可以组合查找。
- 筛选按钮正确显示已选条件数量，重置后归零。
- 列表和日历展示同一批真实数据，并响应相同筛选条件。
- 五类演示数据在对应状态下可见，主要操作与当前真实流程一致。
- 原有安排、改期、取消、确认、催反馈、面试官评价、下一轮、增加面试官、Offer 和淘汰数据流没有回归。
- 前端代码检查、类型检查、构建、相关测试及后端全量测试通过。
- 使用招聘专员和面试官账号完成浏览器验收。

## 明确不做

- 不恢复旧版 Mock 数据和旧路由。
- 不修改后端数据模型、接口协议或技术栈。
- 不把城市、部门等所有条件常驻铺在页面上。
- 不把所有操作按钮重新放回每一行。
- 不在本次范围内重做面试官端页面。
