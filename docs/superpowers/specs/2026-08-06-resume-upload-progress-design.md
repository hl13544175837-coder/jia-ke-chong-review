# 简历上传弹窗解析状态同步设计

## 问题

简历后台已经解析成功并写入候选人数据，但上传弹窗仍保留首次上传响应中的 `processing` 状态，持续显示转圈，造成“解析没有完成”的误解。

## 目标

- 后台解析成功后，弹窗停止转圈并显示“解析成功”。
- 后台解析失败后，弹窗停止转圈并显示可执行的失败提示。
- 网络慢或单次刷新失败时继续显示“解析中”，不误报失败，不重复上传。
- 不修改后端解析、数据库写入、上传接口或文件保存逻辑。

## 方案

复用简历库已有的 3 秒候选人状态刷新结果，把上传结果中的 `candidate_id` 与候选人列表对应起来：

- 候选人 `parse_status=ok`：弹窗行更新为成功。
- 候选人 `parse_status=failed/original_confirmed`：弹窗行更新为待确认，并显示现有错误信息。
- 候选人仍为 `pending/processing` 或本次查询失败：保持解析中。

3 秒是查询间隔，不是超时时间。解析任务不会因前端查询失败被取消。

## 验证

- 回归测试证明：初始 processing 在候选人变为 ok 后更新为成功。
- 回归测试证明：网络未返回新状态时仍保持 processing。
- 运行相关前端测试与生产构建。
