# Agent 简历导入 MVP 验收记录

验收日期：2026-08-07

## 结论

本地 Test 候选通过。在线简历库与完整简历库保持独立；外部 Agent 可以只导入选中的在线简历，也可以把完整简历直接导入现有简历库。智聘不反向控制 Agent，也没有新增自动关联、自动移动或自动删除。

## 真实接口证明

使用 Flask 真实路由和临时数据库执行 6 个组合场景，结果为 `6 passed`：

- 招聘专员导入并读取自己的在线简历。
- Agent 再次同步时保留招聘专员人工修改，并合并完整聊天记录。
- 在线简历硬删除后，已统计的导入数量不减少。
- 月度看板只统计本人、当月的在线简历导入数量。
- 关闭简历 AI 后，Agent 仍可把结构化完整简历和原始文件直接导入现有简历库。
- 招聘专员替换完整简历后，同一外部导入编号仍不会重复创建候选人。

完整简历导入还验证了：加入招聘需求失败时不留下候选人、空批次或成功收据；多文件中已成功的项目不受后续失败影响。

## Ego 外部进程实测

另行启动一套隔离智聘环境，由 Ego 浏览器自己的 Node 进程通过 HTTP 完成真实导入，不复用 Flask 测试客户端：

- 在线简历接口返回 `created=1`，智聘反查到所属招聘专员、具体 Demand、BOSS 账号、结构化在线简历和 2 条完整聊天。
- 完整 PDF 接口返回 HTTP 202 和 `status=ok`，智聘反查到原始文件、结构化内容、具体 Demand、`pending` 流程阶段和不可变导入收据。
- 全部使用虚拟候选人和临时数据库；隔离服务、Ego任务空间和临时数据已在核验后关闭或清理。
