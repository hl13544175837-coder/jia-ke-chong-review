## 2. 优化前后与风险

| 优化点 | 优化前 | 优化后 | 风险度 |
|---|---|---|---|
| 二面账号与任务 | 本地缺少稳定的二面试用账号，任务接力容易卡住 | 安全补齐 `interviewer02`；已有账号绝不覆盖，二面任务明确归属 | 中 |
| 面试完成与评价 | 面试官不能顺手确认并评价，流程容易断 | 只允许所属面试官在面试开始后确认，随后直接填写评价 | 中 |
| 跨轮评价 | 二面可能过早看到一面结论，也可能看到不该看的 HR 信息 | 二面提交前只看一面“已完成”；提交后只读查看；Offer/HR/未来轮始终隐藏 | 高 |
| 今日待办 | 提醒分散，紧急任务不突出 | 待评价、超时、两小时内任务按紧急程度显示并可直达 | 低 |
| 评价内容 | 主要靠一段备注，后续不好比较 | 统一为满意度、岗位匹配、建议、优势、顾虑、备注 | 中 |
| 面试轮次 | 面试名称和第几轮可能选错 | 一面固定第 1 轮、二面固定第 2 轮、三面固定第 3 轮，前后端双重拦截 | 中 |
| 详情页 | 信息挤在一起，按钮位置不稳定 | 固定为“面试信息 / 候选人简历 / 面试评价”三个页签，底部动作固定 | 低 |
| 重复候选人 | 容易误以为系统会直接覆盖或合并 | 只显示疑似重复数量，不自动删除、不自动合并、不自动覆盖 | 高 |
| 页面规范 | 左上角标题大小、状态选中样式不统一，Offer 使用横线 | 主页面统一标题组件；状态选中统一绿色实心框 | 低 |
| 本地文案 | 页面会出现“企业微信待接入”等当前无法完成的提示 | 只说明本地站内日程和待办，不承诺外部能力 | 低 |

风险度表示改动本身需要多小心，不代表当前还有故障。所有中高风险点都加了后端限制和自动测试。
