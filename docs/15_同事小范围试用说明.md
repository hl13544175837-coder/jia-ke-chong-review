# 智聘 · 同事小范围试用说明

## 1. 本轮目标

本轮允许公司内部同事使用真实招聘需求和真实候选人数据，先验证以下六个核心流程是否稳定可用：

1. 招聘需求创建与查看。
2. 简历上传、人工确认和入库。
3. 候选人进入对应需求并按阶段推进。
4. 面试安排、完成确认和面试评价。
5. Offer 保存、审批、发送、接受和入职。
6. 招聘进度与数据看板同步更新。

AI 简历解析、AI 岗位画像、BOSS 自动化、OA 自动审批和外部消息通知本轮不作为放行条件。内部试用配置默认关闭两类 AI，避免外部模型变慢时拖住核心业务。

## 2. 开始前由负责人确认

- 部署版本来自本次独立试用分支，并且流水线全部通过。
- 数据库、简历附件目录和备份目录都是可长期保留的路径，不是 `/tmp` 临时目录。
- 已完成一次备份预演和一次真实备份，并记录恢复点。
- 使用正常账号密码登录；不要开启免登录或测试网关。
- 先由一名招聘专员跑通一条完整流程，再逐步增加同事人数。

严格配置可参考 [`backend/internal-trial.env.example`](../backend/internal-trial.env.example)，启动前用下面的命令检查：

```bash
cd backend
../.venv/bin/python scripts/check_pilot_readiness.py \
  --profile internal-trial \
  --env-file internal-trial.env
```

看到所有检查通过后再启动服务。

## 3. 推荐试用顺序

1. 招聘专员新建一条 1 HC 招聘需求，确认需求编号和负责人正确。
2. 在该需求下上传一份简历。由于 AI 关闭，系统保留原件并提示人工确认。
3. 补全候选人姓名等基本资料并保存，确认候选人自动进入该需求的“待筛选”。
4. 在招聘进度中推进到面试，安排面试官和时间。
5. 面试官完成评价；确认评价本身不会偷偷替招聘专员推进候选人。
6. 招聘专员确认后推进到 Offer，按保存 → 提交 → 审批 → 发送 → 接受 → 入职完成流程。
7. 回到招聘需求、招聘进度和数据看板，确认入职人数、阶段和 HC 数字一致。

## 4. 本轮重点观察

- 页面打开后不白屏、不一直转圈，失败时能看到大白话提示和重试入口。
- 重复点击保存、安排面试、提交评价或推进阶段，不会生成重复记录。
- 候选人始终属于选定的招聘需求，不会串到其他需求或其他招聘专员名下。
- 面试评价只记录结论，不自动推进流程；Offer 入职后才更新入职数字。
- 切换页面再返回时筛选条件可保留，已经关闭的详情不会自动重开。
- 同一问题重试后，系统不会产生两个 Offer、两场相同面试或重复候选人阶段。

## 5. 怎么反馈问题

请按下面格式记录，尽量不要只写“不能用”：

```text
测试账号：例如 hr01
招聘需求编号：例如 REQ-20260813-001
候选人 ID：例如 128
所在位置：例如 面试管理 > 待安排
操作步骤：先点了什么，再点了什么
实际结果：页面发生了什么
期望结果：你认为应该发生什么
是否刷新后恢复：是 / 否
截图或相关文件：
```

发生阻断问题时先停止继续操作该记录，保留页面和编号，由负责人判断是修复后继续，还是恢复到试用前备份。
