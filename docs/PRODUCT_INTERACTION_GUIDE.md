# 智聘独立整合版产品交互文档

## 1. 本次交付是什么

这是一个只服务于本次验收的独立电脑端项目，不会读取或修改其他产品。

- 主产品 `5190`：保留 Readdy 的页面风格和主要交互，并把招聘需求、需求内选人/上传、候选人库、业务筛选、面试、Offer、入职、工作台和站内通知接到同一套真实后端。
- 接口版 `5192`：保留公司招聘业务前端、独立 Flask 后端、登录桥和 GitHub 图片简历解析能力，供研发后续接真实接口时参考。
- 后端 `5010`：独立 Flask + SQLite 本地验收数据；页面刷新和重新登录后仍存在。
- 登录桥 `5110`：给接口版和自动化鉴权实验提供本地登录映射，正式主入口不使用它。
- 公司登录鉴权沿用原协议；OA、企业微信、邮件、短信、候选人触达、正式 LLM/视觉模型密钥和生产部署不在本地闭环内，页面不会冒充这些外部动作已完成。
- 只验收电脑端，不做手机端。

## 4. 关键交互

### 工作台与招聘管理

- 招聘专员工作台读取真实需求、候选人、业务筛选、面试、Offer 和通知；面试官工作台读取本人的业务筛选与面试任务。接口失败显示“数据暂不可用”，不显示假 0。
- 岗位列表支持搜索、状态切换、筛选、排序和阶段下钻。
- 岗位详情支持编辑名称，保存后当前详情立即更新。
- 点击需求可在同一页打开“当前需求候选人”：按城市、学历、技能、来源、阶段、流程状态、最低技能分和操作状态筛选，服务端分页，查看完整简历，勾选加入当前需求。
- 右侧可直接拖入 PDF/DOCX/图片/ZIP，上传时自动关联当前需求，不要求先去简历库。
- 岗位没有配置技能时显示“岗位技能尚未配置/匹配度未知”，不把未知写成 0 分。

### 简历库

- 支持姓名/职位搜索、状态页签、来源、负责人、部门、经验、学历、性别、标签和最近动态筛选。
- 支持 PDF、DOC、DOCX、JPG、JPEG、PNG、WebP、GIF 和 ZIP。
- 图片与 ZIP 在本地走演示解析，导入后新增候选档案、来源和结果提示。
- 候选人库用于跨需求检索、暂时不用、淘汰后可复用和收藏的人选；日常为某个岗位选人优先从需求页完成。
- 招聘专员可查看中文结构化简历和原始文件，在有权限的 Demand 内加入流程并推送业务筛选；已进入后续阶段的人不会再次出现错误的推送动作。

### 面试、Offer 与看板

- 业务筛选结果回到招聘专员候选人页；通过后未安排显示“安排面试”，已有安排显示“查看/调整面试”。
- 面试管理支持真实安排、调整、取消、确认完成、反馈结果和候选人历史。过去时间、同一面试官一小时冲突、面试开始前确认/评价都会被拦截。
- 面试反馈后，招聘专员可安排下一轮、增加面试官、进入 Offer 或填写原因淘汰。
- Offer 支持真实草稿、审批、记录发放、接受/拒绝、跟进、撤回、过期和确认入职；候选人接受后锁定一个可用名额，撤回后释放，只有确认实际入职才增加已入职 HC。
- “记录为已发放”只表示 HR 已把外部事实登记到系统，邮件/短信并未由本系统发送。
- 进度看板支持阻塞分析、招聘专员和总览三种视图。
- 月份按钮会真实切换报表月份并显示结果提示。

### 系统设置

- 通用设置可保存公司名、系统名和招聘周期。
- 用户可以新增、编辑、停用和重新启用。
- 角色权限勾选后可以保存演示状态。
- 部门可以新增、编辑和删除。
- 招聘流程阶段可以上移、下移，首尾按钮明确禁用。

## 5. 交互与业务验收口径

核心招聘按钮不仅要“点得动”，还必须写入后端并在刷新后保持；状态变化后按钮文案和可执行动作必须同步变化。前端隐藏动作不算安全边界，后端仍需校验角色、组织、Demand、阶段、时间、冲突和必填原因。

以下 ZIP 数量是 2026-07-24 的界面同构历史记录，不代表 2026-07-27 的业务闭环验收：

原 ZIP 静态清单：

- 718 个交互控件。
- 其中 479 个原生按钮。
- 原版存在 3 个完全没有处理逻辑的按钮。
- 原版存在 11 个点击后只显示“功能开发中”的占位操作。

整合后的主产品：

- 758 个交互控件，完整覆盖原版 718 个；5 个不安全的假登录/假角色标签由公司真实鉴权控件替换，其他缺失数为 0。
- 502 个原生按钮，包含原版业务按钮和新增的公司鉴权操作控件。
- 没有处理逻辑的按钮为 0。
- “功能开发中”占位操作为 0。
- 所有无法在当前状态执行的按钮使用 `disabled`；可执行按钮必须导航、筛选、切换、打开弹窗、下载或产生可见状态变化。

复跑严格审计：

```bash
node frontend/tests/readdy_zip_exact_parity.test.mjs
```

该测试会逐文件核对原 ZIP 控件标签与数量，并只允许明确登记的 5 个公司安全替换，同时检查空按钮、占位文案、24 条路由和图片/ZIP 格式。

## 8. 本地与外部边界

- 主产品招聘主线的业务状态保存在独立 SQLite 数据库和上传目录，刷新、关闭标签页或换账号后不会恢复成前端初始假数据。
- 筛选条件、当前弹窗和未提交表单属于页面临时状态，刷新后可以重置；已提交业务记录不能丢失。
- 不连接公司真实候选人数据，不保存真实密钥。
- OA、企业微信、外部日历、邮件、短信和候选人自助答复未接入；系统只保存站内任务和 HR 的事实登记，并明确提示“待接入”。
- 彻底删除时只删除本隔离根目录，见 [ISOLATED_CLEANUP.md](ISOLATED_CLEANUP.md)。
