# 智聘独立整合版产品交互文档

## 1. 产品范围

本版本面向少量公司同事在电脑端内网试用。它以公司招聘项目为业务底座，吸收 Readdy 导出前端的页面结构与交互，并迁入 GitHub 图片简历识别能力。

- 主要设备：电脑浏览器，建议宽度 1280px 及以上。
- 本轮不做手机端验收。
- 当前本地演示使用独立 SQLite 数据库和演示账号。
- 正式接口、公司网关和视觉模型密钥由研发后续接入；前端调用位置和错误状态已保留。
- AI 只提供解析、匹配、总结和建议，不自动淘汰、录用、发 Offer 或关闭需求。

## 4. 核心交互

### 登录与工作台

- 使用公司账号形式登录；本地演示桥将账号映射到独立后端。
- 账号错误、密码错误、网络失败都会显示明确原因。
- 工作台数字卡可点击下钻；提醒项进入对应需求、候选人或风险事实。
- 头像菜单提供修改密码和退出登录。

### 招聘管理

- 可按状态、关键字、部门、城市、招聘负责人和创建时间筛选。
- 点击职位、负责人、HC、阶段或状态，在右侧打开对应详情，列表筛选和滚动位置保留。
- “新建需求”展开完整责任单；职位模板、部门、城市、HC、负责人等关键字段有校验。
- 暂停、关闭、转派和调整优先级均要求明确输入并进入审计，AI 不代替用户执行。

### 简历库与上传

- 简历库支持姓名、公司、学校、岗位、技能、城市、来源、解析状态和流程状态筛选。
- “快速查看”打开候选人摘要；“查看完整档案”进入完整简历与流程记录。
- 选择目标招聘需求后，才开放加入需求流程的按钮；未选择时按钮禁用并给出原因。
- 上传支持多选和拖拽：PDF、DOCX、JPG、JPEG、PNG、WebP、GIF、ZIP。
- ZIP 会逐份处理并跳过非简历文件；图片识别结果明确要求人工复核。
- 未配置正式视觉模型时会给出可理解的配置提示，不会伪造识别结果。

### 候选人流程

- 先选择具体招聘需求，再查看待筛选、AI 初筛、业务待反馈、面试中、Offer、已入职等阶段。
- 点击候选人打开流程详情；推进、淘汰、修正、转需求和历史均有独立入口。
- 写操作提交期间按钮锁定，失败保留原状态并提示重试，避免连点产生重复写入。

### 面试管理

- 列表和日历视图可切换，搜索会实时收窄候选人、岗位和面试官。
- 已排期任务提供查看/调整、确认完成、未进行和更多操作。
- 待安排任务打开完整安排表单：需求、候选人、轮次、面试官、时间、地点和备注。
- 面试官从“我的面试”进入反馈表；包含追问参考、评分、建议、原因分类、维度评价、优势和顾虑。
- 提交反馈只完成本轮任务，后续推进或淘汰仍由 HR/经理确认。

### Offer、看板与设置

- Offer 页面区分审批中、已发放、已接受、已拒绝和撤回，并保留审批/状态动作。
- 进度看板按招聘需求展示 HC、漏斗、停滞、待补反馈和责任人，可继续下钻。
- 流程口径用于配置阶段时限和风险口径。
- AI 助手入口保留真实后端契约；本地没有正式密钥时明确提示，不假装成功。
- 系统设置包含账号管理、审计日志和 AI 边界三类；低频创建账号表单按需展开。

## 5. 按钮与状态规范

- 可见且可用的按钮必须产生导航、筛选、弹窗、抽屉或真实请求。
- 暂时不可操作的按钮必须使用 `disabled`，并通过悬停标题说明原因。
- 异步提交展示处理中状态并暂时锁定，防止重复提交。
- 危险动作不使用一键静默执行，必须经过原因、确认或权限校验。
- 紧凑表格按钮保持单行，不允许文字被裁切或覆盖相邻内容。

项目提供静态交互审计：

```bash
cd frontend
npm run audit:interactions
```

## 6. 接口边界

| 前端入口 | 本地演示 | 研发后续接入 |
| --- | --- | --- |
| `/api/*` | 代理到独立后端 `127.0.0.1:5010` | 公司招聘后端/网关 |
| `/pgs/oauth/*` | 代理到独立登录桥 `127.0.0.1:5110` | 公司统一 OAuth 网关 |
| 图片简历识别 | 保留安全上传与错误提示，不保存真实密钥 | 百炼视觉模型或研发选定服务 |
| AI 助手 | 保留请求、流式展示和失败状态 | 研发配置正式 LLM 与审计策略 |

任何真实密钥都不写入仓库。候选人真实数据投入前，仍需研发完成鉴权、隐私授权、持久存储、备份与审计复核。
