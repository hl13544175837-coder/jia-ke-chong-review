# 07 · 上线部署前关键清单（AI 可执行版）

> 版本：2026-07-11 ｜ 状态：demand-scoped P0 代码候选执行清单，具体完成状态以现场复核为准
> 读者：执行型 AI（Codex 等）+ 人类负责人（李小明 / 公司 IT）
> 目标：把经过现场复核的内测基线安全部署到公司服务器，供少数 HR 用**真实数据**小范围试点。
> 关联：本清单是 `docs/06_试点上线检查清单.md`（C1–C13）的 AI 执行视图，逐项给出**判定依据、命令、验收标准、红线**。

> 接手提醒：本文不是“当前已经完成”的记录，也不是普通开发任务清单。只有用户/负责人明确要求执行上线准备时，AI 才能按本文逐项操作；涉及 `.env`、数据库、上传文件、备份、真实账号、真实数据、服务器和公网访问的动作，必须先拿到现场信息和负责人确认。

> `demand_id` P0 已形成合并前代码候选。SIT 演示数据允许清空或重建，可按 `AGENTS.md` 的测试环境授权例外处理；Git 推送不等于构建或部署，生产和真实数据仍执行下列完整门禁。

> 当前宽松 RC/SIT 会设置 `ALLOW_INSECURE_SIT_STARTUP=true`，它只能服务于单人、可丢弃数据测试。执行本真实数据/上线清单时，必须先改为 `ALLOW_INSECURE_SIT_STARTUP=false`；否则 `check_pilot_readiness.py` 应当失败。

## 给 AI 的执行总则（务必先读）

1. **红线不可破**（见 06 清单 §0 / ADR-0001 / ADR-0002）：架构保持 React + Flask 模块化单体；`demand_id` schema 变更只能走版本化 Alembic revisions，不在应用工厂或多 worker 中执行 DDL/回填；歧义数据不猜测。
2. **不提交密钥**：任何真实密钥、API Key 只写进服务器 `backend/.env`，绝不进 git。确认 `.env` 在 `.gitignore` 内。
3. **改动可逆优先**：配置类改动先改 `.env`，不改 `config.py` 读取逻辑。涉及代码处只做已被 06 清单认可的安全加固。
4. **每项必须验收**：完成一项后运行该项「验收命令」，把实际输出贴回，再进入下一项。
5. **遇到需要人类判断的项（标 🧑 HUMAN）**：不要自行决定，停下并向负责人报告所需信息。
6. **运行时基线**：Python 3.11–3.13（推荐及容器基线 3.12），Node.js 20.19–20.x 或 22.12+；前端用 `npm ci` 复现 lockfile。

## 历史基线（仅作参考，不代表当前状态）

> 以下记录 2026-06-22 一次本机检查的观察，用来解释“为什么需要这些硬门槛”。**执行时不要据此判断当前是否已完成**——当前状态必须以现场 `git status --short` 和 `python backend/scripts/check_pilot_readiness.py` 的输出为准。

- 当时 `JWT_SECRET` 17 字符 < 生产要求 32、`FLASK_DEBUG=true`、`DATABASE_URL` 仍为本地 SQLite、`.env` 缺多个生产键，自检 13 项里 11 项 FAIL。
- 这些 FAIL 说明服务器侧必填配置当时还没填，不代表脚本本身失败，也不代表现在仍未完成。

> 关键机制：代码和容器默认 `FLASK_DEBUG=false`；`backend/app/__init__.py::_enforce_production_security` 在「非 TESTING、debug 未显式开启且 `ALLOW_INSECURE_SIT_STARTUP=false`」时触发。它会强制 JWT 强度、严格 CORS origin、AI 合规确认、隐私告知地址、人工复核承诺和显式绝对持久 `UPLOAD_FOLDER`；任一不满足即 `RuntimeError`。CORS 不只是非空，还拒绝 `*`、`null`、用户凭据、路径、query、fragment 和非 HTTP(S) scheme，且错误不回显凭据/query secret。

## 关键清单（按优先级，1–5 为硬门槛，缺一不可对真实用户开放）

### 1. 生成强随机 JWT_SECRET〔配置 · 对应 C1〕
- **为什么**：`JWT_SECRET` 必须 ≥32 字符且非弱默认值，否则令牌可被伪造，等于无认证。生产护栏会在 `FLASK_DEBUG=false` 时强制校验，不达标直接拒绝启动。
- **AI 动作**：
  ```bash
  python3 -c "import secrets; print(secrets.token_urlsafe(48))"
  ```
  将输出写入服务器 `backend/.env`：`JWT_SECRET=<生成串>`，并设 `JWT_EXPIRY_HOURS=8`。
- **验收**：`python3 -c "import os;from dotenv import load_dotenv;load_dotenv('backend/.env');s=os.environ['JWT_SECRET'];print(len(s)>=32 and s not in {'dev-secret-change-in-prod','dev-secret','test-secret','change-me-in-production',''})"` 输出 `True`。
- **红线**：只改 `.env` 取值，不改 `config.py` 读取逻辑（R5）。

### 2. 关闭调试模式〔配置 · 对应 C1〕
- **为什么**：`FLASK_DEBUG=true` 会暴露堆栈、开启交互式调试器（可远程执行代码）。
- **AI 动作**：`backend/.env` 设 `FLASK_DEBUG=false`、`LOCAL_SCHEMA_COMPAT=false`，并设置指向持久卷的绝对 `UPLOAD_FOLDER=/var/lib/zhipin/uploads`。
- **验收**：启动后访问不存在路由返回标准 401/404 JSON，不出现 Werkzeug 调试页。
- **依赖**：设 false 会激活生产安全校验，须确保第 1、4 项已达标，否则启动报 RuntimeError（预期行为）。

### 3. 切换 MySQL/PostgreSQL + 定时备份〔部署 · 对应 C3 · 🧑 HUMAN 协同 IT〕
- **为什么**：SQLite 是单文件、并发弱、随容器重置易丢失，无法搬到服务器；真实简历试点必须用 MySQL 或 PostgreSQL 并配每日备份。
- **AI 动作**：可先 `cp backend/lightweight-pilot.env.example backend/.env`，再把占位值替换为 IT 提供的 MySQL/PostgreSQL、域名、LLM Key 和强密钥；MySQL 使用 `DATABASE_URL=mysql+pymysql://<user>:<pass>@<host>:3306/<db>?charset=utf8mb4`，PostgreSQL 使用 `DATABASE_URL=postgresql://<user>:<pass>@<host>:5432/<db>`；配 `BACKUP_DIR=/var/backups/zhipin` 并交付一个每日 `mysqldump`/`pg_dump` 的 cron/systemd-timer 示例。启动、备份、恢复和清理日志只允许输出 driver/host/database 的脱敏 label，不得打印用户名、密码或 query。
- **验收**：当前代码候选能连接目标库，且 `alembic current == 20260711_04`；备份必须恢复到同引擎临时库，并核对用户、候选人、Job、Demand、Flow/Pipeline、Interview、Offer、Event 和 uploads。仅有 dump 文件不算通过。
- **红线**：如目标为 MySQL，当前恢复脚本未实现/未验收时，必须由 DBA 完成临时库恢复并留证；否则禁止 Backfill/Cutover。

### 4. CORS 收紧到公司域名〔配置 · 对应 C2〕
- **为什么**：生产校验要求 `CORS_ORIGINS` 是严格的 origin 白名单；空值、`*`、`null`、带用户凭据/路径/query/fragment 的 URL 或非 HTTP(S) scheme都会使后端拒绝启动。开发模式留空表示不配置跨域白名单，不得解释成生产可用。
- **AI 动作**：`backend/.env` 设 `CORS_ORIGINS=https://<公司前端内网域名>`（多个用逗号分隔）。若用同源托管 dist 方案，也须填该域名以通过校验。
- **验收**：非白名单域名的浏览器跨域请求被拦；同源页面正常。

### 5. 启用 HTTPS（公司证书 + Nginx 反代）〔部署 · 对应 C4 · 🧑 HUMAN 协同 IT〕
- **为什么**：简历含个人隐私，明文 HTTP 传输不合规。
- **AI 动作**：交付 Nginx 反代配置示例（443 → gunicorn 5000，含证书路径占位与安全头）。证书由 IT 提供。
- **验收**：`https://<域名>` 锁标正常；HTTP 自动跳 HTTPS。

### 6. 启用安全响应头与限流〔配置 · 对应 C10〕
- **为什么**：防点击劫持/嗅探、防登录爆破与接口滥用。功能已在代码内置（`config.py` 默认 `SECURITY_HEADERS_ENABLED=true`、`RATE_LIMIT_ENABLED=true`），但生产 `.env` 应显式写明以防误关。
- **AI 动作**：`backend/.env` 显式设：
  ```env
  SECURITY_HEADERS_ENABLED=true
  RATE_LIMIT_ENABLED=true
  RATE_LIMIT_LOGIN=10
  RATE_LIMIT_AGENT_CHAT=20
  RATE_LIMIT_RESUME_UPLOAD=8
  ```
- **验收**：连续登录失败超过阈值返回 429；响应含 `X-Frame-Options` / `X-Content-Type-Options` 等头。

### 7. 确认关闭公开注册〔配置 · 对应 C6/权限〕
- **为什么**：v0.5 改为管理员发号；不能让外部自助注册。代码默认 `ALLOW_PUBLIC_REGISTRATION=false`，但生产应显式写明。
- **AI 动作**：`backend/.env` 设 `ALLOW_PUBLIC_REGISTRATION=false`。
- **验收**：调用注册接口返回禁用提示；仅管理员可建号。

### 8. 清理演示数据 + 建真账号〔数据 · 对应 C6 · 🧑 HUMAN 确认后执行〕
- **为什么**：仓库带的 demo 账号、样例候选人/岗位/流程和测试简历文件，混入真实数据会污染 BI 和审计。部署现场必须先清演示数据，再由 admin 建真实试点账号。
- **AI 动作**：使用 `backend/scripts/cleanup_demo_data.py`。默认先跑 dry-run：
  ```bash
  python backend/scripts/cleanup_demo_data.py --dry-run
  ```
  人类负责人确认备份目录、数据库和清理范围后，先进入停写窗口并停止应用 worker/异步任务，才允许执行：
  ```bash
  python backend/scripts/cleanup_demo_data.py --confirm
  ```
  脚本幂等，执行删除前会生成带 manifest/SHA-256 的标准可恢复快照，manifest 记录 `uploads.source_root`，以便恢复到新挂载目录时重基址候选人附件路径；旧快照无此字段时只允许同根恢复。随后删除 `@mvp.local` demo owner 及包括 `candidate_demand_flows` 在内的关联业务事实，并且只删除这些事实独占引用的上传文件；真实 owner、无关文件和跨范围引用会保留，混合归属会阻断。
- **验收**：DB 中无目标 demo 账号及关联事实；其独占上传文件已删除，真实数据和无关文件仍在；BI 仅反映保留数据；快照已在临时位置验证可恢复。
- **安全**：没有负责人确认、没有成功快照不得加 `--confirm`。MySQL 自动确认清理被明确禁止，只允许 dry-run 后由 DBA 走同引擎备份恢复和受审计方案。

### 8.1 多组织初始化核对〔权限 · 对应 C6/C11〕
- **为什么**：生产级多组织隔离依赖 `org_id`，如果用户、岗位、候选人、流程、面试、BI 和 AI 对话归属不一致，会出现“看不到应该看的”或“改 ID 看见别人组织”的风险。
- **AI 动作**：上线前抽查数据库：每个真实组织至少有一个管理员；真实用户、岗位、候选人、上传批次、流程、面试、反馈、通知、AI 对话和事件表均有正确 `org_id`；不存在真实数据默认混在 demo 组织。
- **验收**：组织 A 的管理员、招聘专员、面试官分别用修改 ID 的方式访问组织 B 的候选人、岗位、面试、反馈、BI、审计日志和 AI 对话，均返回 401/403/404。

### 8.2 固定 BOSS Cookie 加密密钥〔安全 · 对应 C6〕
- **为什么**：BOSS 直聘是实验辅助能力，不属于 HR 试点主流程必测项；但 `/api/boss/*` 路由已注册，Cookie 会写入 `boss_accounts.cookies_encrypted`。测试/生产如果没有固定合法 `FIELD_ENCRYPTION_KEY`，Cookie 导入会失败，或开发临时 key 重启后旧账号无法解密。
- **AI 动作**：生成 Fernet key，并写入服务器 `backend/.env`：
  ```bash
  python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  ```
- **运行期依赖边界**：同时显式设置 `BOSS_CLI_AUTO_INSTALL=false`。请求处理期间不会下载或安装 CLI，旧 `true` 会被忽略；如独立开放 BOSS，CLI 必须在镜像构建阶段固定、审查并通过 `BOSS_CLI_BIN` 指定。
- **验收**：`python3 backend/scripts/check_pilot_readiness.py` 中 `FIELD_ENCRYPTION_KEY` 输出 PASS；不得在日志、文档或提交中打印真实 key。

### 8.3 demand_id 迁移与 Cutover〔数据/发布 · 对应 C13 · 🧑 HUMAN 协同业务/DBA/运维〕

- **为什么**：一旦同 Job 并行多 Demand，旧代码不能表达新数据，代码回退不等于数据回滚。
- **AI 动作**：RC/SIT 真正空库由 entrypoint 在 Gunicorn 前显式 bootstrap（只接受空库，部分 schema 拒绝），已有库再 `alembic upgrade head`；当前代码候选 head 是 `20260711_04`。生产按 `docs/10_demand_id迁移与回滚手册.md` 由唯一 migration job 执行 Expand → Audit → Backfill dry-run/审批映射 → Verify → Dual-write/Shadow-read → Strict cutover，应用工厂和业务 worker 不执行 DDL。
- **业务门禁**：多 Demand 歧义 bundle 必须有批准映射；不允许默认选最新 Demand。
- **技术验收**：`alembic current == 20260711_04`；核心事实 `demand_id` 无空值；`job_id == demand.job_id`；歧义/孤儿/跨组织错配为 0；每条旧事实恰好映射一次。revision 02 使用 `lower(trim(status))` 识别取消态，并在创建主面试安排和 assignment feedback 唯一索引前检测重复；revision 03 增加 Demand 可空默认面试官外键；revision 04 规范化需求编号并建 `(org_id, request_no)` 唯一索引。`verify_demand_scope.py` 的 `assignment_slot_conflicts` 必须为空。发现冲突必须中止并人工裁决，不自动选赢家。`/api/health` 只证明 liveness，不证明数据库/schema ready。
- **SIT 验收**：同 Job 两个 Demand、同候选人转需求、不同负责人、主/辅面试官、未反馈任务取消重排、已有反馈禁止取消、Offer/HC/BI/审计均不串账；legacy job-only 零 Demand 返回 404、多 Demand 返回 409 `demand_id_required`。
- **证据**：CFPD SHA、Libra CommitID、schema revision、audit/backfill/verify 报告、同引擎备份恢复证据、后端版本、前端资产哈希、验证人和时间。
- **回滚红线**：Parallel Demands 启用前可回退兼容应用并保留加性 schema；启用后只能向前修复，或停写后整体恢复 cutover 前数据库 + uploads 快照。

### 9. 收尾未提交改动 + 跑通验收门禁〔验收 · 对应 C7〕

- **AI 动作**：先重新运行 `git status --short`，再按主题精确提交；不得将未跟踪 plan/spec、其他分支 WIP 或当地输出夹带入发布。然后按本文和 SDD 的当前门禁执行：
