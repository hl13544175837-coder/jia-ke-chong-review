智聘系统
消费 MQ 并校验验签、幂等、字段映射；失败进入重试和审计，不重复建单。
创建 / 更新 Demand形成 JD、HC、负责人和状态明确的招聘责任单。
触发资料推送记录触达结果和失败原因。
保存面试安排关联 Demand、候选人、轮次、面试官与时间。
开始 30 分钟后发评分卡接收逐项 0～10 分和 Yes / No；只记录事实，不自动推进。
等待 HR 决策AI 可总结和建议，但不能替 HR 推进、淘汰或发 Offer。
发起并跟踪 Offer向 OA 发起审批，展示审批、发放、签署、接受 / 拒绝状态。智聘 → OA
更新入职状态与 HC正式入职才已入职人数 +1、剩余 HC -1；放弃则释放。
招聘专员
接手招聘需求核对需求、负责人、目标日期与 HC，开始招聘。
选择候选人与面试官确认资料范围后触发推送。
人工确认时间和形式与候选人确认线上 / 线下，并通知候选人；邮件或短信待业务确认。
人工选择下一步进入下一轮 → 回到阶段 5；直接录用 → 阶段 9；不通过 → 终结。面试反馈本身不推进流程。
发起 Offer 申请填写 Offer 申请并提交 OA；审批驳回时补充后重提。
面试官
接收必要候选人资料只查看本次任务所需信息。
接收日程和会议信息确认时间、会议链接或地点。
参加面试围绕岗位和 JD 完成本轮面试。
填写评分与推荐意见逐项 0～10 分，并提交 Yes / No；不直接决定流程结果。
候选人
确认可面时间并接收通知候选人不使用企业微信；由招聘专员人工联系。
参加面试线上进入会议，或前往线下面试地点。
在现有系统签署 / 拒绝 Offer接受后进入待入职；发出或接受 Offer 均不扣减 HC。
正式入职 / 延期 / 放弃最终事实由 HRIS 回传，不由候选人在智聘中操作。
循环分支：招聘专员选择“进入下一轮”后，指定下一轮负责人，并回到阶段 5“确认时间与安排”，重新执行会议 / 日程 → 面试 → 评分反馈。
方向不能画反需求进入是 OA → 智聘；Offer 发起是智聘 → OA；HRIS 入职结果是 HRIS → 智聘。
候选人通知不算企微接口候选人不使用企业微信。邮件或短信渠道、入职提醒时间仍待业务确认。
终态名称待确认候选人不通过、拒绝 Offer 或未入职，最终归为“淘汰、终结或人才保护”仍需业务定稿。
HC 只在正式入职时扣减Offer 发出、签署或接受都不减 HC；以 HRIS 正式入职事实为准。
